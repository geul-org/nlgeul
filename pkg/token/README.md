# token

`nlgeul token`의 읽기. 토큰(음절) 스트림을 조각으로 가르고 어절로 끊어 올리는 데까지만 한다(실험, 설계는 작업 문서 `token-stream-algorithm.md`). 문장성분은 정하지 않는다. `Reader.Stream(문장)`이 결과를 구간마다 구조(`Segment`)로 한 번에 하나씩 내고, `Reader.BoxLines`가 그것을 상자로 찍은 글줄을, `Reader.JSONSentence`가 `--format json`의 한 줄을 돌려준다.

밖에서 import해 쓰는 패키지다(`github.com/geul-org/nlgeul/pkg/token`, 옛 자리 `internal/token`). 옮긴 까닭은 [pkg/README.md](../README.md)에 있다.

## 공개 API

패키지 밖에서 보이는 이름 전부다. 스트림으로 읽는 쪽은 `New`, `Reader.Stream`, `Stream`의 메서드, 아래 구조 타입만 쓰면 된다. `BoxLines`·`Cuts`·`Marks`는 `nlgeul token`의 출력과 측정용이고 패키지 안의 것에 기대어 있어 함께 왔다.

| 이름 | 꼴 | 뜻 |
|---|---|---|
| `New` | `func New(o Options) (*Reader, error)` | 색인을 짓고 낱말 표를 읽은 `Reader`. 문법 표(`pkg/data/*.tsv`)는 실행 파일에 들어 있어 따로 읽지 않는다. 낱말 표는 한 번 읽고 `Reader` 하나로 문장을 몇 개든 읽는다 |
| `Options` | `Words string`, `Layers int`, `Spacing []string` | 낱말 표 경로(비면 없음), 쓰는 겹 수(0은 전부), 켤 띄어쓰기 조항(비면 끔) |
| `SpacingArticles` | `[]string` | 띄어쓰기 조항 이름 전부(`Options.Spacing`에 쓰는 이름) |
| `Lambda` | `const Lambda = 15` | 정렬 공식에서 성립의 무게(결정 014-35) |
| `Reader.Stream`, `Reader.StreamTrace` | `func (r *Reader) Stream(sentence string) *Stream` | 문장을 스트림으로 연다(`StreamTrace`는 `--trace` 줄도 `Notes`로 꺼낸다) |
| `Stream.Next`, `Stream.Again` | `Next() (Segment, bool)`, `Again(region Span) (Segment, bool)` | 다음 구간의 1등 갈래, 그 구간의 다음 갈래. 마디의 후보는 전부 담는다 |
| `Stream.NextHead`, `Stream.AgainHead` | `NextHead(head int) (Segment, bool)`, `AgainHead(region Span, head int) (Segment, bool)` | `Next`·`Again`과 같고, 마디마다 후보를 λ 차례 앞의 head개만 돌려준다(0 이하는 전부). 아래 "후보 수 한도" |
| `Stream.Notes` | `Notes() []string` | 지난번 뒤로 보낸 구간들의 trace 줄(구간을 읽으며 나온 줄과 문장 단위 규칙의 줄) |
| `Segment` | `Region Span`, `Rank int`, `Ways *big.Int`, `Nodes []Node`, `Lambda float64` | 한 구간의 갈래 하나 |
| `Node` | `Span Span`, `Contest Contest` | 마디: 어절 하나와 그 후보경합 |
| `Span` | `Start, End int` | `[Start, End)`, 빈칸을 뺀 문장의 글자(rune) 위치 |
| `Contest` | `Unit int`, `Glued bool`, `Text string`, `Branches []Branch`; `Plural() bool` | 경합. 마디의 경합이면 `Branches`가 후보들(λ 차례) |
| `Branch` | `Words []Eojeol`, `Verdict float64`, `Pref float64`; `Lambda() float64`, `String() string` | 후보 하나: 성립, 선호, λ(= 선호 + `Lambda`·log10(성립), 성립이 0 이하면 −∞) |
| `Eojeol` | `Parts []Part`, `End int`, `Attach bool`; `String() string` | 어절 하나의 조각들 |
| `Part` | `Text`, `Hidden`, `Name Name`, `Stem`, `Unseen`, `Written`, `Depth`; `Known() bool`, `Label() string`, `String() string` | 조각 하나. `Known`은 줄기가 새 낱말(`새 낱말`)일 때만 거짓 |
| `Name` | `Kind, Form string`; `String() string` | 조각의 풀이 하나 |
| `Reader.JSONSentence` | `func (r *Reader) JSONSentence(sentence string, index int) JSONSentence` | `--format json`의 한 줄(구간마다 1등 갈래, 후보 전부) |
| `JSONSentence`, `JSONSegment`, `JSONWord`, `JSONCandidate`, `JSONPart` | 구조체(JSON 칸 이름은 아래 "JSON 출력") | `--format json`의 꼴 |
| `Reader.BoxLines` | `(sentence string, trace bool, head int) []string` | 상자 출력(기본 출력) |
| `Reader.Cuts`, `Reader.Marks` | `(sentence string) []string` | 측정용 `--cuts`, `--marks` |

받은 구조는 읽기만 한다. 스트림이 들고 있는 마디·후보와 같은 조각(슬라이스)을 함께 쓰므로 고치면 같은 스트림이 나중에 주는 갈래가 바뀔 수 있다.

밖에서 쓰는 예는 `example_test.go`(`Example`)다: 시험용 낱말 표(`testdata/words-stream.tsv`)를 한 번 읽고, 문장 둘을 스트림으로 읽어 `NextHead(2)`로 구간마다 1등 갈래를 받고, 1등 갈래의 1위 후보에 새 낱말(`Known()`이 거짓)이 낀 구간에서만 아는 말로만 끊은 갈래가 나올 때까지 `AgainHead`로 다음 갈래를 받는다(`고양이가`는 없고, `방돌에`는 둘째 갈래 `방 │ 돌에`).

### 여러 고루틴에서 쓰기

`Reader` 하나를 고루틴 여럿이 함께 쓰지 않는다. `Reader`는 문장을 읽는 동안 판정을 기억하는 표(아래 "판정 기억")에 쓰고, 그 표에는 자물쇠가 없다. 병렬로 읽으려면 일꾼(고루틴)마다 `New`로 `Reader`를 따로 만든다(낱말 표를 일꾼마다 한 번씩 읽는다). `Reader`가 같은 낱말 표와 같은 옵션으로 만들어졌으면 어느 `Reader`가 읽든 같은 문장의 결과는 같으므로, 문장을 일꾼에게 나눠 주고 결과를 문장 차례대로 모으면 한 줄기로 읽은 것과 같다.

### 판정 기억

추적 줄을 찍지 않을 때 색인은 그래프에 물은 것과 그 답을 기억한다(`index.judged`, 키는 그래프·조각의 사실 전부(`rule.Piece`)·낱말의 글자). 같은 물음은 그래프를 다시 돌리지 않는다. 키가 그래프에 주는 것 전부이므로 기억한 답은 다시 물은 답과 같다. 기억한 수가 `judgedMax`(100,000)가 되면 전부 버리고 다시 쌓는다. 한도는 메모리만 묶고 결과는 바꾸지 않는다. 추적(`--trace`)은 기각 이유가 필요해 늘 그래프를 돌린다.

## 올려 보내는 구조

위층(어절 층)은 글줄을 쪼개지 않고 이 구조를 받는다. 스트림 마디의 경합(`Node.Contest`)이 이 `Contest`이고, `internal/combo`도 `[]Contest`를 받는다. 상자 출력(`BoxLines`, 아래 "상자 출력")과 JSON 출력(`JSONSentence`)은 스트림이 보낸 이 구조를 찍을 뿐이다(후보 글자는 `Branch.String`).

```go
r, _ := token.New(token.Options{Words: "words.tsv"})
st := r.Stream("작은 곰이 물을 마신다.")
for seg, ok := st.Next(); ok; seg, ok = st.Next() {
	for _, n := range seg.Nodes {
		best := n.Contest.Branches[0]
		last := best.Words[len(best.Words)-1].Parts
		_ = last[len(last)-1].Name // 끝 조각의 풀이: {꾸밈 은} …
	}
}
```

| 타입 | 칸 | 뜻 |
|---|---|---|
| `Contest` | `Unit` | 문장의 몇째 단위에 든 경합인가(0부터) |
| | `Glued` | 문장에서 이 경합과 바로 앞 경합 사이에 빈칸이 없는가(문장의 첫 경합은 거짓. 한 단위 안의 둘째 경합부터는 참이고, 단위의 첫 경합은 앞 단위 뒤에 빈칸이 없으면 참). 스트림이 채우고 상자 출력에는 찍지 않는다(`--format json`에서는 어절의 `glued`). `+`로 갈린 단위와 여닫는 기호에서 갈린 단위·경합이 붙어 있었는지를 알려 준다 |
| | `Text` | 그 구간의 글자 |
| | `Branches` | 갈래들, 나은 것부터. 하나면 확정, 둘 이상이면 후보가 둘 이상인 경합(`Plural()`) |
| `Branch` | `Words` | 어절들. 단위 안에 경계가 선 갈래는 둘 이상이다 |
| | `Verdict`, `Pref` | 성립(조각 verdict의 최솟값), 선호 |
| `Eojeol` | `Parts` | 조각들. 줄기가 먼저, 그 뒤가 표지 |
| | `End` | 단위 안에서 이 어절이 끝나는 자리(토큰 수) |
| | `Attach` | 줄기 없이 표지만 있는 어절인가. 띄어 쓴 표지 단위(`로`, `에서`, `인데`)를 앞 단위에 붙는 표지로 읽은 것이고, `+로[부사격:로]`처럼 `+`로 시작하게 찍는다 |
| `Part` | `Text` | 글자. 줄기는 찾는 꼴(되돌린 줄기, 불규칙의 본디 줄기, 줄임이 가리키는 낱말, 오표기 줄기의 바른 꼴) |
| | `Hidden` | 글자에 안 보여 풀어 쓴 부분(`(ㄴ)다`의 `ㄴ`, 빠진 `(이)`의 `이`) |
| | `Name` | 풀이 하나. 한 조각에 풀이가 하나씩이고, 풀이가 여럿인 자리는 후보가 따로 나온다(`가[주격:가]`와 `가[보격:가]`). 이름 없는 줄기는 빈 `Name{}`이다 |
| | `Stem` | 줄기인가(아니면 표지: 조사, 선어말, 맺음, 단위, 기호) |
| | `Unseen` | 글자에 흔적이 전혀 없는 조각인가 |
| | `Depth` | 여닫는 기호의 깊이(`([열기:2]`와 `)[닫기:2]`는 2: 바깥에 묶음 하나가 열려 있다. 여는 기호 없이 선 짝 없는 닫기 `”[닫기:0]`은 0)와 제목의 단계(`##[제목2]`는 2). 그 밖에는 0 |
| | `Written` | 틀린 표기로 적힌 줄기 또는 표지가 글자에 적힌 꼴. 줄기는 낱말 표 또는 이 층의 닫힌 표가 다른 낱말의 틀린 표기로 적은 것(`맞기`, `꺼`. 합쳐진 조각을 떼어 되돌린 꼴, 빗금·붙임표로 묶인 줄기는 묶음 전체 `입력/역활`), 표지는 닫힌 표의 틀린 맺음(`ㄹ께`, `읍니다`). 그 밖에는 빈 문자열. 찍을 때만 이름 끝에 `,오타정정:맞기`로 덧붙고 `Name`에는 들지 않는다. 그 부분의 `Text`는 바른 꼴(표지는 `게`, `Hidden`은 `ㄹ`) |
| `Name` | `Kind`, `Form` | 풀이의 갈래(`주격`, `꾸밈`, `열쇠`, `맺음`, `수`, `경로` …)와 꼴(`가`, `은`, `체언` …). 갈래만으로 다인 것은 꼴이 비어 있다 |

- 한 단위의 경합은 이 차례로 나온다: 글자 앞에 붙은 기호마다 하나, 후보들이 모두 합의한 구간마다 하나, 글자 뒤에 붙은 기호마다 하나(`?[물음표]`, `.[마침표]`는 줄기 없는 조각 하나짜리 어절이다). 경합의 `Text`를 차례로 이으면 빈칸을 뺀 문장 그대로다: 입력 글자는 하나도 빠지지 않는다.
- 표가 모르는 줄기(새 낱말)는 `Name`이 비어 있다. 낱말 표가 준 갈래는 후보마다 하나다(`지금[열쇠:체언]`과 `지금[열쇠:부사]`는 두 후보다. 각각 `{열쇠 체언}`, `{열쇠 부사}`). 닫힌 집합 낱말이 낱말 표에도 그 갈래로 있으면 집합의 이름(`수[의존명사:수]`)과 낱말 표의 갈래(`수[열쇠:체언]`)가 따로 후보다.
- 수, 주소·경로·옵션, 여닫는 기호와 코드는 줄기 조각이고 이름이 그것을 말한다(`{수}`, `{경로}`, `{열기 1}`, `{닫기 2}`, `{코드}`). 여닫는 기호의 깊이는 이름의 꼴(`"1"`)과 `Depth`(1) 양쪽에 있다. 이름이 붙지 않은 기호(`->`, `*`)는 이름 없는 줄기 조각 하나짜리 경합이고 글자 그대로 찍힌다.
- 추적(`--trace`)은 구조에 없다. `StreamTrace`의 `Notes`로 꺼내고, `BoxLines`가 그 단위의 상자들 앞에 찍는다.

## 스트림 인터페이스

위층(hypo)이 문장을 한 구간씩 받는 길이다. 문장을 한 번에 다 읽어 주지 않고, 받는 쪽이 청할 때 읽는다(고루틴·채널 없음, 함수 호출로 당겨 감). 이 층은 받는 쪽의 상태를 들지 않는다: 같은 문장은 중간에 무엇을 청했든 같은 결과를 낸다.

```go
type Span struct{ Start, End int }      // [Start, End): 문장의 글자 위치, 빈칸은 세지 않음
type Node struct {                      // 마디: 어절 하나
	Span    Span
	Contest Contest                     // 그 어절의 후보경합: 후보는 모두 낱말 하나(Words가 하나), λ 내림차순
}
type Segment struct {                   // Next·Again이 보내는 것: 한 구간의 갈래 하나
	Region Span                         // 구간(후보가 모두 합의한 자리 사이)
	Rank   int                          // 갈래 순위, 1부터
	Ways   *big.Int                     // 그 구간의 갈래(끊는 꼴) 수(큰 수). 1이면 띄어 쓴 보통 어절
	Nodes  []Node                       // 갈래의 어절들, 위치 차례
	Lambda float64                      // 갈래의 λ 합: 마디마다 λ 1위의 합
}
func (r *Reader) Stream(sentence string) *Stream
func (r *Reader) StreamTrace(sentence string) *Stream   // 읽은 단위의 --trace 줄을 Notes로 꺼냄
func (s *Stream) Next() (Segment, bool)                 // 다음 구간의 1등 갈래. 끝이면 false
func (s *Stream) Again(region Span) (Segment, bool)     // 그 구간에서 마지막으로 보낸 갈래의 다음 갈래
func (s *Stream) NextHead(head int) (Segment, bool)                // Next, 마디마다 후보는 앞의 head개(0 이하는 전부)
func (s *Stream) AgainHead(region Span, head int) (Segment, bool)   // Again, 마디마다 후보는 앞의 head개(0 이하는 전부)
func (s *Stream) Notes() []string                       // 지난번 뒤로 보낸 구간들의 trace 줄(한 번 꺼내면 비움)
```

```go
st := r.Stream("아버지가방에들어가신다")
seg, _ := st.Next()          // 구간 [0-11]의 λ 1등 갈래: 아버지[0-3] 가방에[3-6] 들어가신다[6-11]
seg2, ok := st.Again(seg.Region) // 같은 구간의 다음 갈래(Rank 2). 더 없으면 ok가 false
```

- 후보 수 한도(`NextHead`, `AgainHead`): 받는 쪽의 한도일 뿐이다. 갈래·마디·후보는 `Next`·`Again`과 똑같이 만들고(탐색 중에 버리는 후보는 없다), 돌려줄 때 마디의 후보경합을 λ 차례 앞의 head개로 자른다(`segmentHead`). 그래서 head를 준 결과는 head 없이 받은 후보 목록의 앞 head개와 같다(같은 λ의 차례도 같다). 구간·순위·`Ways`·`Lambda`(마디마다 λ 1위의 합)는 바뀌지 않는다. head가 0 이하면 `Next`·`Again`과 같다. 자른 마디는 복사본이라 스트림이 든 갈래는 건드리지 않고, 같은 스트림에서 head 있는 것과 없는 것을 섞어 불러도 차례는 그대로다(시험 `TestStreamNextHead`, `TestStreamAgainHead`). 한도가 계산을 줄이지는 않는다.
- 문장 단위 규칙(색인의 `sentence` 목록, `sentenceRule`: 이름, toulmin 그래프, 주장이 설 때 더하는 선호 `bonus`, 어느 후보를 묻는가 `about`, 그 가운데 뒤 어절을 서술어까지 읽어야 판정할 수 있는 후보 `waits`. 뒤를 읽지 않는 규칙은 `waits`가 없다): 어절의 후보 하나를 같은 문장의 둘레 어절과 함께 판정한다.
  - 묶어 읽기: `Next`는 구간 하나를 읽어 줄 세운 뒤, 그 구간의 1등 갈래 어절 가운데 `waits`에 걸리는 후보를 가진 어절이 있으면 서술어가 나올 때까지 구간을 더 읽는다(`Stream.hold`, `heldAfter`, `waitsFor`). 서술어는 1위 후보가 맺음·꾸밈·이름 조각을 지닌 어절이다(`predKinds`, `nearOf`의 `Pred`). 서술어 없이 문장이 끝나면 거기까지 읽고 판정한다. 기다리는 후보가 없으면 구간 하나만 읽는다(규칙이 없을 때와 같다).
  - 판정: 아직 판정하지 않은 구간들(`unjudged`)의 1등 갈래 어절을 한 줄로 놓고(`seatsOf`, `seatsIn`, `seat`) 앞 어절부터 차례로, 어절의 후보마다 그 후보를 묻는 규칙의 그래프를 돌린다(`Stream.settle`, `judgeSeat`, `judgeCandidate`). 1등이 아닌 갈래에만 있는 어절은 판정하지 않는다. 그래프는 컨텍스트 `rule.KeyAround`의 `rule.Around`를 읽는다: 후보 자신(`Self`), 앞 어절들(`Before`, 가까운 것부터: 줄의 앞 어절은 그 어절을 판정한 뒤의 1위로, 그보다 앞은 이미 판정한 어절들 `Stream.behind`), 뒤 어절들(`After`, 가까운 것부터, 읽은 그대로의 1위). 어절마다 `rule.Near`(줄기, 줄기의 이름, 마지막 조각의 이름, 서술어인가, 표지들의 이름)로 적는다(`nearOf`, `nearsBack`, `nearsOn`). `rule.Listed`의 사실 `ListSelfStem`·`ListSelfKind`·`ListSelfLast`·`ListPrevLast`·`ListPrevKind`·`ListPrevStem`·`ListNextStem`·`ListNextLast`·`ListNext2Stem`과 `rule.SelfHas`(후보의 표지 가운데 하나, `ListSelfMarks`)가 이것을 묻는다(`pkg/rule/README.md`). 규칙의 그래프는 `sentenceClaim`이 주장(규칙 이름으로 찍힌다)과 함께 만든다.
  - 올림: 주장이 서면(verdict > 0) 그 후보의 선호에 규칙의 `bonus`를 더한다(`lift`: 어절의 `Span`과 후보의 글줄로 짚는다. 규칙 여럿이 서면 모두 더한다). 후보를 지우거나 낮추지 않는다. 더한 뒤 그 어절의 후보를 λ 차례로 다시 놓고 구간의 갈래를 처음부터 다시 센다(`region.lift`, `lifted`, `raised`). 그래서 `Next`·`Again`·`NextHead`·`AgainHead`가 주는 후보 차례·λ와 `Segment.Lambda`(마디마다 λ 1위의 합)는 모두 올린 뒤의 값이고, `Again`도 올린 뒤의 λ 차례로 갈래를 준다. 창이 끊은 구간은 올림을 들고 있다가 `Again`이 그 구간을 다시 짤 때 같은 올림을 건다(`redoAgain`).
  - `--trace`: 규칙이 물은 후보마다 한 줄을 쓴다: `  · <후보>\t<규칙 이름>\t<verdict>\t통과` 또는 `  · <후보>\t<규칙 이름>\t<verdict>\t기각: <까닭>`(까닭은 걸린 예외의 이름). 구간을 읽으며 나온 줄과 그 구간 어절의 규칙 줄은 구간이 들고 있다가(`region.notes`) `Next`가 그 구간을 보낼 때 `Notes`로 나간다. 그래서 묶어 읽어도 줄은 그 어절의 상자 앞에 찍히고, 뒤 구간의 줄이 앞 구간의 `Notes`에 섞이지 않는다. 구간이 가져가지 않은 줄(`Stream.pending`)은 마지막 `Next`(false) 뒤에 나간다.

    - `bonusSentence`는 문장의 사정(앞뒤 어절)을 읽은 규칙이 더하는 값이고, `bonusOrder`는 문맥 없이 같은 글자의 두 이름 사이 차례만 정하는 규칙이 더하는 값이다(같은 λ의 두 후보를 가르기에는 넉넉하고 다른 끊기를 넘어서지는 않게 작다). 두 값을 고른 기록은 `consts.go`의 주석에 있다.

- 구간 하나는 살아남은 후보가 모두 합의한 자리 사이다. 구간 안에서 끊는 꼴이 갈린 후보는 갈래가 된다: 갈래 = 끊는 꼴 하나 = 마디(`Span`)의 줄. `Ways`는 그 구간의 서로 다른 끊는 꼴의 수이고 `math/big`의 큰 수다(덩어리가 길면 갈래 수는 지수로 커져 어느 정수에도 안 든다. 아는 후보가 없는 구간은 0). 합의한 자리가 없으면 구간이 길어진다(붙여 쓴 `아버지가방에들어가신다`는 구간 `[0-11]` 하나, 갈래 수백). 구간을 안에서 자르는 규칙은 없다.
- 위치의 단위는 문장의 글자(rune)이고 빈칸은 세지 않는다. 마디 경합의 `Text`는 그 `Span` 자리의 글자다.
- 마디는 `Span`으로 한 번만 만든다(두 갈래가 함께 쓰는 마디도 하나). 마디의 후보 = 그 `Span`에 낱말을 놓는 모든 끊는 꼴의 낱말의 합집합이고, 같은 글자(`Eojeol.String()`)는 한 번만 둔다(처음 나온 것. 값이 다른 같은 글자는 나은 쪽 `stepBefore`, 아래 `registry.twins`). 마디의 후보는 낱말 하나에 조사·어미가 붙은 것뿐이다. 낱말이 둘 이상인 읽기는 마디가 둘 이상인 갈래다. 덩어리 전체를 낱말 하나로 읽는 후보(새 낱말)는 덩어리 전체 마디 하나짜리 갈래로 남는다.
- 후보의 λ = 선호 + `Lambda`·log10(성립)이다(`Lambda` = 15, 결정 014-35. `internal/combo`도 이 값을 쓴다). 성립이 0 이하면 −∞. 같은 λ는 낱말이 생긴 차례(`born`: 한 단위를 읽는 동안 낱말(시작·끝·찍은 꼴)이 처음 나온 차례의 번호, 앞 낱말과 상관없다. 번호가 없는 후보(기호, 단위 후보)는 같은 λ에서 뒤로, 번호가 같으면 넣은 차례). 마디의 성립·선호는 `Branch`가 속에 들고 있는 낱말별 값(`stretch`가 채움)이고, 단위 안에서 시작하는 마디의 선호에는 경계 비용(`costBoundary`)이 그대로 들어 있다. 보조 용언이 돌려받는 `back`은 후보 차례에만 쓰이므로 마디의 값에는 들지 않는다.
- 갈래는 λ 합이 큰 차례로 하나씩 꺼낸다(마디 그래프에서 최선 우선 탐색, 같은 값이면 넣은 차례). 요청이 올 때마다 다음 하나만 만든다. 한도는 없다. 마디를 이어 붙여 만든, 원래 끊는 꼴에 없는 줄은 내지 않는다.
- `Next`는 `Again`과 상관없이 구간을 차례로 보낸다. 단위(띄어쓰기 사이, 여닫는 기호)는 필요할 때 하나씩 읽는다. 후보가 없는 구간은 마디 없는 `Segment`(`Rank` 0)로 간다.
- 구간을 끊는 꼴의 목록으로 만드는 일은 `cutsOf`(경합 → 끊는 꼴)와 `newRegion`(끊는 꼴 → 구간)으로 나뉘어 있다. 다른 출처의 끊는 꼴은 `newRegion`에 목록으로 더하면 된다.
- 스트림은 글자를 그물로 읽는다(`scan.net`, `readUnitNet`). 낱말 뒤에 오는 낱말이 앞 경로에서 묻는 것은 마지막 낱말뿐이므로, 역마다 후보를 마지막 낱말(상태)로 합치고(`merged`: 같은 낱말은 상태 하나, 앞 상태들은 `preds`에 한 번씩) 경로를 펼치지 않는다. 끝까지 닿는 상태(산 상태)에서 모두가 합의한 역을 구해 구간을 가르고, 구간마다 마디(상태가 선 `Span`)·간선(앞 상태 → 상태)·갈래 수(`Ways`, 상태 집합을 키로 하는 부분집합 셈, 큰 수)·갈래의 맞음(낱말 사슬이 이어지는가, `weave.member`)을 구한다. 그래서 구간은 낱말 수에 비례해 한 번만 읽고(경로 수와 상관없다), 갈래는 요청마다 하나만 꺼낸다. 마디·후보·갈래 차례·λ 합은 단위를 통째로 읽어 `contests`·`newRegion`으로 자르던 옛 방식과 같다(테스트 `TestNetEqualsOld`). 같은 글자로 찍히는 낱말 둘의 값이 다르면 옛 방식처럼 나은 쪽(경로 차례와 같은 차례, `stepBefore`) 하나만 마디에 둔다(`registry.twins`는 그런 낱말 수). 옛 읽기(`Cuts`·`Marks`의 `unitScan`+`search`, 단위를 통째로 읽는 `readUnit`)는 그대로 경로를 펼쳐 읽는다. 긴 붙여 쓴 덩어리에서는 경로가 지수로 늘어 메모리가 터지므로 긴 입력은 스트림(기본 출력)으로 읽는다. 여닫는 기호에 글자가 붙은 단위는 스트림에서 `readOntoNet`이 읽는다: 기호와 글자 뒤 기호는 옛처럼 경합이고, 기호 뒤 글자(`ps`)는 그물로 읽되 단위 전체를 읽는 그물(`planter`: 단위 머리와 기호 뒤에서 시작하는 낱말만 만든다)에서 첫 낱말(기호를 뗀 것)과 기호만 선 상태 뒤 낱말을 그 끝 역에 심는다(`ontoStretches`). 옛 `readOnto`는 `readUnit` 안에 남는다(스트림의 `ontoReader`는 단위 머리의 기호 부분만 `readUnit`에 넘기므로 실행 중에는 닿지 않는다).
- 창 10음절(`windowSize`, 단계 7-3): 긴 단위(띄어쓰기·짝 기호 사이의 긴 글자)는 끝까지 읽고 구간을 쌓는 대신 `Next`가 다음 구간이 나올 때까지만 그물을 짠다(`netRun`, `unitReader`: 고루틴·채널 없음). 마지막 끊은 역 c에서 `tokens(c, J) >= 10`이 되면 역마다 끊기를 시험한다. 창 끝 상태 F = 끝 역이 J에서 10 tokens 안인 상태, 낱말 표의 긴 키(>10)가 아직 맞고 있는 자리(`keyPrefixes`), 창 안에서 끝나는 긴 아는 낱말이 시작할 수 있는 자리의 상태. F 상태마다 c부터 가는 되짚기(마디의 λ 1위 합이 가장 큰 앞 상태 사슬, `reach`)의 마디 줄을 구해 모두가 같은 앞부분(`commonSpans`)에서 앞 마디부터 q를 시험하고, 구간 [c, q](`between`)의 1등 갈래가 그 앞부분과 같으면 q에서 끊는다. 끊은 구간의 갈래는 그 구간 안에서만이고 다음 구간은 앞 구간 1등 갈래의 마지막 마디에 선 상태들(`lastStates`)에서 시작한다(씨앗 `seed`: 마지막 낱말만 지니고 앞이 없는 상태; 막히면 q에서 끝나는 상태 전부로, 그래도 없으면 남은 글자는 읽기 없는 구간 `Rank 0`). q를 가로지르거나 씨앗에서 닿지 않는 상태는 버려진다(`prune`, `reroot`). 그래서 덩어리 전체를 새 낱말 하나로 읽는 후보와 단위 전체를 앞 단위에 붙는 표지로 읽는 후보(`attached`)는 한 번이라도 끊으면 사라지고, 창보다 긴 새 낱말(줄기 10음절 + 꼬리)이나 꼬리가 창보다 긴 낱말은 놓칠 수 있다. 창으로 끊은 구간은 보낸 뒤 글자 범위와 씨앗만 남기고(`redo`) `Again`이 그 구간만 같은 scan에서 다시 짜서 준다(`redo.rebuild`; 가장 최근 다시 짠 구간 하나만 들고, 다른 구간으로 옮겼다 돌아오면 보낸 순위만큼 건너뛴다). 창으로 끊기 전에 단위 끝에 닿는 단위(짧은 단위)는 창이 없을 때와 같고, 여닫는 기호에 글자가 붙은 단위의 기호 뒤 글자도 같은 창으로 읽는다(`ontoReader`: 단위 전체를 읽는 그물의 낱말 심기는 첫 끊기 전까지). 창을 끄는 내부 스위치는 `index.noWindow`(내보내지 않는 칸)이고 `Stream`의 `stats`(`netStats`)가 끊은 횟수·창 폭·첫 구간까지 짠 역 수·열린 상태 수 최댓값·막힘/넓힘/읽기 없는 구간 수를 센다. `Cuts`·`Marks`는 창과 상관없다.
- 새 낱말 줄기 10음절(`newStemMax`): 낱말 표·닫힌 집합에 없는 새 낱말은 줄기만 10음절(`tokens` 셈, 조사·어미는 세지 않음)까지 후보가 된다. 덩어리(단위) 전체를 새 낱말 하나로 읽는 후보와 단위 머리(짝 기호·코드 묶음)는 길이와 상관없이 남는다. 낱말 표·닫힌 집합·바뀐 꼴·틀린 꼴의 키와 슬래시·붙임표로 묶은 줄기는 길이 제한이 없다(색인의 `farKeys`·`farBases`, 줄기 시작 자리 `beginnings`/`farBegins`). 점수(성립·선호·λ)와 후보 차례는 그대로이고 먼 자리의 새 낱말 후보만 만들지 않는다.

## JSON 출력

`nlgeul token --format json`의 읽기. `Reader.JSONSentence(문장, 번호)`가 스트림(`Stream`)에서 `Next`만 불러(`Again` 없음) 구간마다 1등 갈래를 `JSONSentence`로 모아 돌려주고, `cli`가 이것을 JSON 한 줄로 찍는다. 후보는 전부 담는다(`--head`는 상자의 보여 주기 한도일 뿐). 꼴과 칸의 뜻은 저장소 `README.md`의 `JSON 출력`에 있다.

| 타입 | 칸 |
|---|---|
| `JSONSentence` | `sentence`, `text`, `segments`, `best_lambda` |
| `JSONSegment` | `region`, `text`, `rank`, `lambda`, `ways`(수, 2^53을 넘으면 문자열), `words` |
| `JSONWord` | `span`, `text`, `glued`, `candidates` |
| `JSONCandidate` | `parts`, `verdict`, `pref`, `lambda`(−∞는 `null`) |
| `JSONPart` | `text`, `name`(없으면 `null`), `known`(`Part.Known()`: `Label()`이 새 낱말이 아님), `restored`(`Part.Unseen`), `hidden`, `stem` |

`region`·`span`은 `Segment.Region`·`Node.Span` 그대로다: 문장에서 공백(`unicode.IsSpace`)을 뺀 글자(rune) 위치, `[시작, 끝)`.

## 상자 출력

`nlgeul token`의 기본 출력이다. `Reader.BoxLines(문장, 추적, head)`가 스트림(`Stream`, 추적이면 `StreamTrace`)만 받아 그린다(`boxLinesOf`: `Next`로 구간마다 1등 갈래를 받고, 갈래가 둘 이상인 구간(`Ways > 1`)이면 `Again`으로 다음 갈래를 받는다). 후보를 만드는 쪽과 `Stream`은 건드리지 않는다. 아래 그림은 시험용 낱말 표(`testdata/words-stream.tsv`)로 `아버지가방에`를 `--head 2`로 돌린 것이다.

```
┌ [0-3] 아버지 ─ 후보경합 3 ───────────────────────────┐ ┬┐ ① λ 합 -8.84
│ 아버지[열쇠:체언]  성립 0.87 선호  -1.97             │ ││
│ 아버+지[맺음:지]   성립 0.33 선호 -11.27             │ ││
│ (1개 생략됨)                                         │ ││
└──────────────────────────────────────────────────────┘ │├ 어절경합 [0-6]
┌ [3-6] 가방에 ─ 후보경합 2 ───────────────────────────┐ ┘│
│ 가방[열쇠:체언]+에[부사격:에]  성립 0.82 선호  -4.72 │  │
│ 가방에                         성립 0.33 선호 -14.14 │  │
└──────────────────────────────────────────────────────┘  │
┌ [0-4] 아버지가 ─ 후보경합 2 ─────────────────────────┐ ┬┘ ② λ 합 -14.38
│ 아버지[열쇠:체언]+가[주격:가]  성립 0.87 선호 -3.61  │ │
│ 아버지[열쇠:체언]+가[보격:가]  성립 0.87 선호 -3.61  │ │
└──────────────────────────────────────────────────────┘ │
┌ [4-6] 방에 ─ 후보경합 2 ─────────────────────────────┐ ┘
│ 방[열쇠:체언]+에[부사격:에]  성립 0.47 선호  -4.95   │
│ 방에                         성립 0.33 선호 -10.10   │
└──────────────────────────────────────────────────────┘
                                                         (1개 생략됨)
1등 길: 아버지 │ 가방에  (λ 합 -8.84)
```

- 마디(`Node`) 하나에 상자 하나, 위에서 아래로 쌓는다. 제목은 `[시작-끝] 어절 ─ 후보경합 n`(n은 마디의 후보 수 전체). 안은 후보 줄: 후보 글자(가장 넓은 후보 폭으로 왼쪽 맞춤), 두 칸, `성립 %.2f 선호 `, 선호(`%.2f`, 가장 넓은 폭으로 오른쪽 맞춤). 후보는 마디 경합의 차례(λ 차례) 그대로다. head보다 많으면 `(k개 생략됨)` 줄이 상자 안 마지막에 든다.
- 어절경합(`Ways > 1`): 갈래를 순위 차례로, 한 갈래 안의 마디는 위치 차례로 쌓는다. 보여 주는 모든 갈래의 상자는 폭이 같다. 상자 오른쪽에 빈칸 하나 뒤로 칸 둘: 안쪽 괄호(갈래, 첫 줄 `┬`, 끝 줄 `┘`, 사이 `│`, 첫 줄 꼬리표 `① λ 합 -11.98`)와 바깥 괄호(어절경합, 첫 갈래의 첫 줄 `┐`부터 보여 준 마지막 갈래의 첫 줄 `┘`까지, 가운데 줄 `├ 어절경합 [시작-끝]`). 갈래가 하나뿐인 구간(`Ways` 1)에는 괄호가 없다. 마디가 하나뿐인 갈래의 안쪽 괄호는 `─`, 갈래가 셋 이상이면 사이 갈래의 첫 줄 바깥 괄호는 `┤`(가운데 줄과 겹치면 `┼`), 갈래 하나만 보여 주면 바깥 괄호는 `├` 한 칸, 한 줄에 꼬리표가 둘이면 두 칸 띄어 잇는다. 동그라미 숫자는 ①~⑳, ㉑~㉟, ㊱~㊿, 그 뒤는 `(51)`.
- head가 0보다 크면 갈래도 head개까지만 `Again`으로 받고(넘는 갈래는 만들지 않는다), 나머지는 어절경합의 마지막 상자 다음 줄에 `(n개 생략됨)`(괄호 칸의 첫 칸에서 시작)으로 센다.
- 마디가 없는 구간(`Rank` 0)은 구간의 글자만 상자 없이 한 줄로 찍고 1등 길에 그 글자를 넣는다. 맨 끝 줄 `1등 길:`은 구간마다 1등 갈래의 마디 글자를 ` │ `로 잇고 λ 합(구간 1등 갈래들의 합)을 적는다.
- 추적은 `Notes`로 받아 그 단위의 상자들 앞에 찍는다.
- 칸 폭(`cellWidth`, `runeWidth`)은 이 저장소 안의 작은 함수다: 결합 문자·폭 없는 문자(U+0300~036F, U+200B~200F, U+FE00~FE0F)는 0칸, 동아시아 넓은 글자(한글, 가나, 한자, 전각, 이모지 등 `wideCells`의 범위)는 2칸, 나머지(상자 문자 포함)는 1칸이다. 상자 문자를 두 칸으로 그리는 글꼴에서는 맞지 않는다. 오른쪽 선이 맞는 것은 한글 두 칸 터미널 기준이다.

## 색인과 그래프

이 층의 닫힌 표 가운데 값의 나열인 것은 `pkg/data/*.tsv`에 있고 `*_table.go`가 `data` 꾸러미로 읽어 변수를 만든다(줄 읽기는 `shortOf`, `contractOf`, `pairOf` 들). 변수 이름은 파일에 남아 있다. 틀린 줄이 있으면 프로그램이 시작할 때 파일 이름과 줄 번호를 대고 멈춘다. 코드에 남은 표도 있다(수사, 불규칙 용언, 합쳐진 글자 들). 표 파일마다의 칸과 줄을 더하는 법은 [pkg/data/README.md](../data/README.md)에 있다.

- 표지 풀이 하나에 toulmin 그래프 하나다(`markerGraph`). 그래프는 문법 표의 한 줄(`parse.ParticleMarkers`, `parse.ClosingMarkers`, 선어말 칸 `slotRows`)과 그 표지로 끝나는 닫힌 집합 낱말 목록에서 찍어낸다. 이름은 `주격:이`, `보조사:은`, `꾸밈:은`, `선어말:었`, `맺음:지만` 꼴이다.
- 그래프의 주장은 "이 자리의 이 토큰 열은 이 표지다"(`rule.PieceRead`)이고, 구조를 보는 예외가 그것을 꺾는다: 앞에 줄기가 없다(`PieceIs`, 기준 `PieceStem`에 `Not`. 가운뎃점(`signs.tsv`에서 이름이 `가운뎃점`인 글자) 바로 뒤의 온 음절 표지도 앞에 줄기가 없는 것으로 친다(`place`): 가운뎃점은 낱말이 아니므로 `갑·+을[목적격:을]`, `읍ㆍ+면[맺음:면]`은 서지 않는다. 서술격 `이`(`copulas`)는 이 막음 밖이라 `갑·+이[서술격:이]+다`는 남는다), 앞 토큰의 끝이 안 맞는다(`PieceAfter`), 조사 사슬에 맞지 않는다(`ChainLinks`), 선어말 칸의 순서(`SlotOrder`), 받침만 붙은 꼴을 읽는 음절이 아니다(`Listed`에 `Not`, 낱말 표가 없을 때만), 통째로 닫힌 집합의 낱말이다(`Listed`). 어/아/여로 시작하는 조각이 앞 모음과 어긋나면 반박 `PieceClash`가 낮춘다(`먹아`는 지우지 않고 뒤로 보낸다). 규칙 함수는 모두 `pkg/rule`의 것이고 기준만 다르다: 참/거짓 사실 하나를 보는 판정은 `PieceIs`, 목록에 있는지 보는 판정은 `Listed` 하나가 기준으로 갈라 맡고, 반대 방향은 기준 `Not`으로 준다. 예외는 왜 꺾는지를 그 노드에 싣고(`except`), `--trace`는 그 노드의 이유를 찍는다.
- 예외 표(`pkg/data/case-exceptions.tsv`, 변수 `caseExceptions`)의 줄은 표지 그래프 하나(그래프 칸, 색인의 이름)와 그 그래프가 읽지 못할 낱말 하나다. 줄이 있는 그래프는 그 줄들의 낱말 목록으로 꺾는 예외를 하나 더 단다(`markerGraph`: `Listed`, 기준 `ListWord`, 목록 이름 `caseExceptions`, 이유 "예외 표의 줄이다"). 판단 중인 낱말(단위의 글자, 조각 끝까지. 닫힌 집합 낱말의 예외와 같은 사실)이 줄의 낱말이면 그 표지 풀이가 기각된다(세기 `지움`). 닫힌 집합 낱말의 예외(`wholeWords`)와는 노드와 이유가 따로다. 이름이 같은 그래프(틀리게 적은 맺음과 `하`의 ㅎ이 합쳐진 꼴의 그래프도)는 모두 그 예외를 단다. 낱말 표를 주면 색인을 지을 때 표가 대는 그래프 이름이 색인의 표지 그래프에 있는지 보고 없으면 오류로 멈춘다(`checkCases`. 낱말 표 없이 지은 색인에는 낱말 표가 있어야 서는 그래프(하오체 맺음, 줄임 맺음 들)가 없어서 보지 않는다). `--trace`는 이 예외가 걸린 줄에서 이유 뒤에 맞은 낱말과 표의 줄을 찍는다(`caseNote`): `기각: 예외 표의 줄이다(<낱말>) — 예외 표 <줄 번호>: <근거 종류> <근거>`(줄 번호는 표 파일의 줄 번호). 지금 표의 줄은 둘이다. 하오체 맺음 `맺음:소`의 `담소`(낱말 표의 명사인데 `담+소`에 지던 것. 근거는 관찰 46/46, 29파일): 그래서 `담소`는 `담소[열쇠:체언]`이 1위이고 `담[열쇠:동사]+소[맺음:소]` 후보는 없다. `적소`, `하오`, `가오` 같은 하오체는 그대로다. 이름 꼴 맺음 `이름:ㅁ`의 `고름`(낱말 표의 명사인데 줄기와 `ㅁ`이 한 음절에 합쳐진 꼴 `고르+(ㅁ)`에 지던 것. 근거는 관찰 30/30, 고름+조사 57자리 25파일 중 30): 그래서 `고름을`은 `고름[열쇠:체언]+을[목적격:을]`이 1위이고 `고르[열쇠:동사]+(ㅁ)[이름:ㅁ]+을[목적격:을]` 후보는 없다. 세기가 지움이라 고르다의 이름 꼴로 쓴 `고름`(`옷을 고름에`)도 체언으로 읽는다. 판단 중인 낱말이 단위의 글자이므로 붙여 쓴 `옷고름에`(낱말은 `옷고름`)에는 걸리지 않는다. `됨을` 같은 이름 꼴은 그대로다.
- **소괄호 한자 병기.** 단위 바로 뒤에 소괄호가 붙고 그 안이 한자로만 단위의 한글 음절 수만큼이면(`대곤(大棍)`, `관치(官治)의`) 그 단위 안의 표지 그래프(`markerGraph`: 조사·맺음·선어말)는 서지 못한다(예외 `PieceIs`, 기준 `PieceGlossed`). 「한글 맞춤법」 부록 문장 부호 소괄호 (2)(우리말 표기와 원어 표기를 아울러 보일 때)대로 그 한글은 한자의 음이어서 음절 가운데 조사·맺음·선어말이 없다. 접미(`접미:…` 그래프)는 꺾지 않는다. 이 근거는 고유어 조사·맺음·선어말의 것이고, 한자어 접미는 병기한 한자 안에 든다(`보장률(保障率)`: `보장[열쇠:체언]+률[접미:률]`). 아는 낱말·새 낱말 읽기는 남는다(`대곤`, `대[열쇠:체언] 곤[열쇠:체언]`. `대[열쇠:동사]+곤[맺음:곤(고는)]`, `관하[열쇠:동사]+치[맺음:지]`는 서지 않는다). 자르는 단계가 단위마다 바로 뒤 소괄호의 한자 수를 적고(`glossAt`, `unit.gloss`. 한자는 유니코드 한자 문자), 단위를 읽을 때 읽는 글자(머리 뒤)가 모두 한글 음절이고 그 수가 같으며 그 글자와 괄호 사이에 떼어 낸 기호가 없는지 본다(`glossedBy`, `scan.glossed`). 사실은 그 단위에서 묻는 조각마다 실린다(`judge`). 머리에 여닫는 기호가 붙은 단위(`"관치(官治)"`)는 기호 뒤 글자를 따로 읽는 스캔에도 넘긴다. 띄어 쓴 괄호(`대곤 (大棍)`), 음절 수가 다른 한자(`대곤(大)`), 한자 아닌 글자가 낀 괄호(`대곤(大棍,)`)는 사실이 아니다. 한자 음은 맞춰 보지 않으므로(음절 수만) 뜻을 단 병기에도 걸린다: `운용한다(行陣和睦)`는 `운용하+(ㄴ)다`를 잃는다(알려진 피해). `markerGraph` 밖에서 지은 그래프(수 뒤 조각 `addAfter`, 서술격 `이` `addCopula`, 합쳐진 글자 `addFused`, `addWide`의 높임 `시`)에는 이 예외가 없다.
- 풀이는 후보마다 하나다. 조사·선어말·맺음은 풀이(색인 항목)마다 조각이 따로이고(`groupAt`의 열쇠에 이름이 든다) 사슬은 풀이마다 제 갈래로 이으며 앞말 판정(`gate`)도 풀이마다 받는다. 낱말 표의 줄기는 갈래마다 후보가 따로이고(`stepsOf`, `knownCandidates`) 그 갈래의 그래프가 낸 성립과 그 갈래의 관측 횟수가 쓰인다(`taken`). 갈래 그래프가 기각한 갈래의 후보는 나오지 않는다. 닫힌 집합 낱말이 두 집합에 들면 집합마다, 기호로 이어진 열의 이름이 여럿이면 이름마다 후보가 따로이고 성립과 선호는 같다. 이름표 안에는 `|`가 없다.
- 받침으로 끝난 이름 뒤의 `이`(`영숙+이+가`)는 이 층만 읽는 표지 `접미:이`다(`innerSuffixes`). 받침 뒤에만 붙고 조사 사슬의 맨 앞자리이며, 뒤에 조사가 이어질 때만 선다(예외 `PieceIs`, 기준 `PieceLast`). 그래서 `고양이가`는 `고양이+가`와 `고양+이+가`가 함께 올라간다. `nlgeul parse`의 조사 표에는 없다.
- 낱말 표가 있으면 표의 체언 바로 뒤의 한자어 접미(`pkg/data/noun-suffixes.tsv`, 지금은 `률` 하나)를 표지 `접미:<꼴>`로 읽는다(`nounSuffixes`, `addWide`: `보장[열쇠:체언]+률[접미:률]+은[보조사:은]`). 사슬 자리는 `접미:들`과 같아(`LinkSuffix`) 뒤에 조사와 서술격이 이어진다(`보장+률+이+다`, `copulaSuffixes`). 앞말 칸은 `ㄴ 아닌 받침 뒤`다(「한글 맞춤법」 제11항 붙임 1: 모음·ㄴ 받침 뒤에서는 `율`로 적는다). 앞말은 그래프 `앞말:체언`(`suffixGateOf`)이 판정하고, 예외는 둘이다: 앞말이 낱말 표의 체언이 아니다(`StemKind`), 줄기와 접미를 합친 글자열이 낱말 표의 낱말이다(`PieceIs`, 기준 `PieceWhole`, `gated`가 채운다). 그래서 통째 낱말이 표에 있으면(`합격률`) 접미 읽기는 서지 않는다. 표에 횟수가 없어 선호는 음절 값이다.
- 서술격 이다(`morphemes.md` 2절)는 줄기 `이`의 그래프 `서술격:이`가 읽는다(`addCopula`, `copulas`). 주장은 "이 `이`는 체언 뒤 이다의 줄기다"이고, 예외는 앞에 줄기가 없다와 이 바로 뒤에 선 맺음이 이다에 붙지 않는 것이다(`Listed`, 맺음 표의 표시). 이 뒤에 선어말이 먼저 서면 그 선어말을 보므로 그런 맺음도 선어말 뒤에서는 선다(`firstName`: `학생+이+었+습니다`, `학생+이+었+는데`). 맺음 아래에 합쳐진 꼴은 풀어 찍는다(`학생+이+(ㅂ)니다`, `학생+이+(ㄴ)`, `문제+이+(었)+다`). 모음 뒤에서 이가 빠진 꼴은 그래프 `서술격:이(빠짐)`이 2절에 적힌 맺음(다, 고, 며, 면, 지만, ㄴ, ㅂ니다) 앞에서만 읽고 `학교+(이)+다`로 찍는다. "모음 뒤"와 "이가 빠지는 맺음의 목록에 있다"는 둘 다 그 그래프의 예외다(`PieceAfter`, `Listed`에 `Not`. 목록은 `droppable`이고 낱말 표가 있으면 `droppableKnown`을 더해 그래프를 짠다). 이와 맺음 사이에 선어말이 끼면 빠진 이로 읽지 않는다. 낱말 표가 있으면 네·냐·니·라·거든·구나·군·야·니까·죠·냐고·더라도·거나·든지·든가와 인용 꼴 라는·라며·라면서·라니와 냐는·냐며·냐면·냐면서·냐니까 앞에서도 읽되, 앞말이 표의 체언이나 의존명사일 때만이다(`droppableKnown`: `거+(이)+네`, `뭐+(이)+냐`, `사과+(이)+라는`). 흔적이 없는 조각이라 3겹에서 값을 치른다. 이다에만 붙는 맺음(에요, 야, 라서 들)은 `서술격:이` 뒤와 줄기 `아니` 뒤에만 서고, 이다를 품은 맺음(예요)은 체언 뒤에 바로 선다. 낱말 표가 있으면 서술격 꼬리는 체언 줄기와 맞는다(`kindTails`). 횟수는 표의 452만이고, 다른 표지의 선호가 달라지지 않도록 표지 횟수의 합에는 넣지 않는다. 이가 빠진 꼴을 읽는 맺음은 다, 고, 며, 면, 지만, ㄴ, ㅂ니다, 라서, 라면, 지, ㄴ지, ㄴ데, ㄴ가, ㄹ까이고 `잖`(지+않) 앞에서도 읽는다(`학교+(이)+라서`, `학교+(이)+지+(않)+아`). 꾸밈 맺음 ㄴ 앞에서는 반박 `Listed`가 낮춘다(관형형 앞에서는 이가 대체로 빠지지 않는다). 낱말 표가 있으면 이름 꼴 맺음 기 앞에서도 읽되, 기 바로 뒤에 조사가 이어질 때만이다(`문제+(이)+기+도`, `문제+(이)+기+는`. `문제기`만으로는 읽지 않는다): 빠진 이의 그래프에 예외 "뒤가 이름 꼴 맺음이다"(`Listed`, `dropNaming`)가 있고, 그 예외를 "바로 뒤에 조사가 붙는다"(`PieceRight`)가 다시 꺾는다. 앞말은 표의 체언이어야 하고, 꾸밈 맺음 앞과 같은 반박이 낮춘다(`dropAdn`). 앞 글자가 한글 음절이 아니면(영숫자 열, 수, 코드, 파일명) 받침이 있는지 글자로 알 수 없다. 그 뒤의 빠진 이는 이다에만 붙는 맺음 `야` 앞에서만 읽는다(`abc+(이)+야`, `droppableRun`): 예외 "앞 글자가 한글 음절이 아니다"(`PieceAfter`)를 "뒤의 맺음이 그 목록에 있다"(`Listed`)가 다시 꺾는다. 이 자리에서는 앞말이 표의 체언인지 묻지 않고, 낱말 표가 있을 때만 읽는다(`야`가 `droppableKnown`의 맺음이다). 다른 맺음(다, 고, 면, 네) 앞의 영숫자 열은 전처럼 그 맺음의 줄기로만 읽는다(`abc+다`). 어하다처럼 본용언의 어/아 꼴에 붙여 쓰는 보조 `하`(`helped`)가 이 뒤에 서는 후보는 두 그래프의 예외 "뒤가 본용언에 붙여 쓰는 보조 용언이다"(`Listed`, 닫힌 표 `copulaBars`)가 기각한다. 뒤에 선 것의 이름은 `afterCopula`가 준다(`학교이어하는`은 `학교+이+어 하+는`으로만 읽고 `학교+이+(어)+하[보조:하]`로 읽지 않는다. 예쁘+(어)+하처럼 용언 뒤의 보조 `하`는 그대로다). 접미 `들`·`씩`·`끼리`(낱말 표가 있으면 `률`도)와 조사 `대로` 뒤에도 서술격이 선다(`afterSuffixes`, 목록은 닫힌 표 `copulaSuffixes`와 `copulaParticles`, 사슬 표의 갈래 `LinkCopula`. 범위·한정의 보조사 갈래 `LinkRange`도 `LinkCopula`를 받고, 어느 조사 뒤인지는 이 목록이 가린다): 서술격 꼬리를 읽은 자리에서 그 앞의 조사 사슬을 한 번 더 읽어 마지막 조각이 그 접미나 조사인 것만 잇는다(`고양이+들[접미:들]+이[서술격:이]+다`, `사과+씩+이+다`, `마당+끼리+(이)[서술격:이(빠짐)]+다`, `뜻+대로+(이)+지`). 사전의 「이다」는 조사 뒤를 들지 않는다. `대로`는 정답지 평가의 정답이 그렇게 읽은 것(정답지 관측)을 따랐다. `뿐`은 넣지 않았다(정답지가 체언 뒤 `뿐이다`를 조사로도 의존명사로도 적어 고침 1, 망침 3). `까지`·`부터` 뒤는 관측이 없어 넣지 않았다. 수 단위 뒤의 후보(`afterUnits`)와 같은 틀이고, 빠진 이가 앞말에 묻는 체언 판정은 접미 앞의 줄기가 받는다. `쯤`과 이름 뒤의 접미 `이`(`영숙이이다`) 뒤에는 서술격을 읽지 않으며, `고양이들이`의 주격 후보는 그대로 선다.
- 두 조각이 합쳐진 글자(`addFused`, 표는 `fused_table.go`, 준말 목록은 `pkg/data/contracts.tsv`). `셨`·`셔`·`십`은 줄기의 끝 음절 `시`에 조각이 합쳐진 것으로 읽는 자리마다 높임 선어말 `시`로도 읽는다(`honors`: `가+시+(었)+다`, `가+시+(어)서`, `가+시+(ㅂ)니다`). 높임 `시`는 모음 뒤에 서고, 받침(ㄹ 아닌) 뒤에서는 이음 `으`가 앞에 선다(`읽+으+시+(었)+다`, 그래프 `이음:으`). 이음 `으`는 조각 하나이고 `시` 앞과 맺음 니·니까·나·냐 앞, 줄기 뒤와 선어말 었·겠 뒤에 선다(`linked`: `읽+으+시+고`, `먹+었+으+니`; 예외 `Listed`에 `Not`). 으를 받는 다른 맺음은 표에 으가 든 꼴이 따로 있다(으면, 은, 을). 으가 든 꼴(은, 을, 음, 읍시다, 으면 …)은 ㄹ 아닌 받침 뒤에만 붙는다(`euAfter`): ㄹ 받침 줄기는 ㄴ·ㄹ·ㅁ과 으 없는 꼴을 받는다(`물 것`, `살면`). 문법 표는 "받침 뒤"로 적고 있어 이 층의 색인에서 좁힌다. 다만 낱말 표가 있으면 ㄹ을 빼지 않고 꾸밈 맺음 `은`·`을`을 붙인 꼴도 표의 용언 줄기 뒤에서 읽는다(`looseClosings`: `줄+은[꾸밈:은]`, `살+을[꾸밈:을]`. 한글 맞춤법 제18항에 어긋난 꼴이고 바른 꼴은 `준`, `살`). 따로 둔 색인 항목이고 ㄹ 받침 뒤에만 붙으며(`AfterLiquid`), 앞말이 표의 용언 줄기여야 하고(`앞말:용언`), 반박 "으가 든 꼴은 ㄹ 아닌 받침 뒤에 붙는다"(`PieceAfter`, 힘은 `forceClash`)가 낮춘다. 표의 꼴대로 읽은 풀이(`줄[의존명사]+은[보조사:은]`, `주+(ㄴ)`)는 그대로 선다. `으면`, `음` 같은 다른 으 꼴은 넓히지 않았다. 줄기 풀이(`마시+(었)+다`)는 그대로 나란히 서고, 낱말 표의 갈래 맞춤이 둘을 가른다. `잖`은 맺음 `지`와 `않`으로 풀고 뒤의 맺음은 `않`에 붙는다(`negated`: `하+(였)+지+(않)+아`). 맺음 `어야`(합쳐진 꼴 포함) 바로 뒤의 `겠`은 `어야 하겠`에서 `하`가 준 것으로 풀어 보조 용언 `하`를 괄호에 적고, `겠`과 뒤의 맺음은 `하`에 붙는다(`obliged`, `mustNames`: `가+(아)야+(하)+겠+다`, `먹+어야+(하)+겠+네`). 같은 단위 안에서 `어야` 뒤에 바로 붙은 `겠`만이다(띄어 쓴 `겠다`는 읽지 않는다). 표의 맺음 `죠`, `십시오`, `시오`, `세요`, `더라`는 조각으로 풀어 찍는다(`splits`: `그렇+지+(요)`, `가+시+(ㅂ)시오`, `가+시+오`, `가+시+(어)+요`, `하+더+라`. `시오`는 하오체 `오`가 높임 `시` 뒤에 서는 것과 같은 풀이라 하나로 합친다. `시오`·`으시오`를 푸는 것은 하오체 `맺음:오` 그래프가 서는 낱말 표가 있을 때뿐이고(`haoSplits`, `splitsOf`), 없으면 표의 맺음 하나로 찍는다: `가+시오[맺음:시오]`). 풀어 찍은 맺음은 조각을 하나씩 읽은 풀이와 같은 갈래라 한 번만 올라간다. 찍힌 이름 가운데 `맺음:ㅂ시오`와 `부정:않`은 그래프가 따로 없는 조각 이름이다. 앞말이 정해진 꼴(`contracts`: 이게, 이건, 이걸, 뭘, 무얼, 누가, 누굴, 누군, 여긴, 여길, 우린, 우릴, 그땐, 땐, 이젠 들과, 대명사 꼴 내·네·제 뒤의 격조사 `게`인 내게·네게·제게(`내+게[부사격:에게]`), 어디·여기·거기·저기 바로 뒤의 `다`·`다가`인 어디다·여기다가 들(`어디+다[부사격:에다]`, `여기+다가[부사격:에다가]`). `게`와 `다`·`다가`는 글자 그대로 적고 표의 `에게`·`에다`·`에다가` 줄의 이름과 횟수로 읽는다. 낱말 표가 있으면 한 음절 대명사에 받침으로 붙은 조사 난·넌·전·날·널·절·걘·얜·쟨도: `shortPronouns`)은 낱말과 그 아래의 조사로 풀고(`fixed`: `이것+(이)[주격:이]`), 뒤에 조사가 더 붙는지는 그 조사의 갈래로 사슬 표가 정한다(`이것+(은)+요`). 닫힌 집합이라 표에 적힌 꼴만 읽고, 낱말 표가 그 낱말을 모르면 꼴의 이름(`줄임:이게`)으로 안다. 일반 낱말 뒤의 받침 조사(`친군`)는 읽지 않는다(갈래 수를 줄이려는 선택이다). 꾸밈 맺음으로 끝난 어절 바로 뒤의 `게`·`건`·`걸`은 의존명사 `거`와 그 아래의 조사다(`하+는 거+(이)`, `하+(ㄴ) 거+(는)`; 예외 `PieceIs`, 기준 `PieceAdn`에 `Not`. 꼬리를 찾는 자리에서는 "어느 후보든 꾸밈꼴이 여기서 끝난다"로 묻고, 후보에 이을 때 그 후보의 마지막 어절로 같은 그래프에 다시 묻는다: `again`). 겹치는 맺음(ㄹ게, ㄹ걸)과 낱말은 지우지 않고 나란히 선다. `거`를 `꺼`로 적은 `껀`·`껄`은 낱말 표가 있을 때 같은 자리에서 읽는다(아래 오표기 줄). 꾸밈 맺음으로 끝난 어절 바로 뒤의 `테`는 의존명사 `터`에 서술격 이다의 줄기가 합쳐진 것으로도 읽는다(`nounCopulas`, `addNouns`, `nounCopula`: `하+(ㄹ) 터+(이)+니까`, `가+(ㄹ) 터+(이)+(ㄴ)데`. `터이니`, `터인데`가 줄어든 꼴이다). 뒤에 이다가 받는 맺음이 바로 붙거나(`테니`, `테고`, `테야`) 받침으로 합쳐진다(`텐데`, `텐가`). 그래프 `줄임:테`의 예외는 셋이다: 앞 어절이 꾸밈 맺음으로 끝나지 않는다(`PieceIs`, 기준 `PieceAdn`에 `Not`. 게·건·걸과 같이 후보마다 다시 묻는다), 뒤의 맺음이 이다에 붙지 않는다(`Listed`), 뒤의 조각이 이 글자의 모음에 합쳐진 어/아나 ㅆ이다(`Listed`, 목록은 `fusedNames`: `터이+어`는 `테`가 아니다). 이는 글자에 흔적이 있어 `(이)[서술격:이]`로 찍고 흔적 없는 조각의 값을 치르지 않는다. 줄기 `터`는 낱말 표가 있으면 표의 체언으로, 없으면 꼴의 이름(`줄임:테`)으로 선다. 낱말 `테`로 읽은 풀이와 같은 글자의 낱말(`테고`, `테지`)은 그대로 나란히 선다.
- 낱말 속에도 흔한 합쳐진 글자(`addWide`, 표는 `wide_table.go`, 줄임 맺음·조사·선어말은 `pkg/data/short-closings.tsv`, `short-particles.tsv`, `short-slots.tsv`)는 낱말 표가 있을 때만 읽고, 다른 풀이를 지우지 않고 나란히 세운다. 앞말이 낱말 표의 용언 줄기(줄어든 조사는 체언)여야 한다: 꼬리가 줄기를 만나는 자리에서 그래프 `앞말:용언`·`앞말:체언`이 판정한다(`gated`, 예외 `StemKind`). 높임 `시`가 든 `신`·`실`·`심`·`세`는 `셨`과 같은 자리(줄기 끝 `시`+조각으로 읽는 곳)에서 `시`를 한 칸 끼워 읽는다(`가+시+(ㄴ)다`, `가+시+(ㄹ)까`, `가+시+(ㅁ)+을`, `가+시+(어)+요`, 받침 뒤 `읽+으+시+…`). 글자의 그래프(`합침:신` 들)의 예외: 받침만 떼어 낸 꼴 바로 뒤에 조사가 붙는다(`PieceRight`, `사신이`. `심`은 예외), 떼어 낸 받침이 뒤 토큰과 표의 맺음을 이루지도 단위가 끝나지도 않는다(`PieceRight`, `사신고`). `세`는 `요` 앞에서만 읽는다. 인용이 줄어든 맺음(`대`, `ㄴ대`, `는대`, `래`, `으래`, `재`, `단`, `ㄴ단`, `는단`, `란`, `으란`, `잔`)과 `진`·`긴`·`길`·`곤`은 한 조각이고 이름에 본디 꼴을 적는다(`간+대[맺음:ㄴ대(ㄴ다고 해)]`, `하+진[맺음:진(지는)]`). `달까`(다고 할까), `ㄴ달까`·`는달까`(ㄴ다고 할까, 는다고 할까), `랄까`(라고 할까)도 한 조각이다. `달까`는 형용사 줄기 뒤에 바로, 동사는 `ㄴ달까`·`는달까`로, `랄까`는 동사 뒤에 서고, 서술격 이다는 `랄까`를 받고 나머지 셋은 받지 않는다(`학생+이+랄까`). 바로 뒤에 조사가 붙으면 기각하고(`요`는 받는다), `대`·`단`은 형용사 줄기 뒤에 바로, 동사는 `ㄴ대`·`는대`로, `래`·`재`·`란`·`잔`은 동사 뒤에 선다(`kindTails`). 줄어든 조사 `선`(에서는)·`론`(로는)·`으론`(으로는)은 `엔`·`에선`처럼 한 조각이고 사슬을 닫는다(`여기+선[부사격:선(에서는)]`). 인용에 과거가 합쳐진 `댔`·`랬`·`쟀`(다고/라고/자고 했)은 선어말 자리의 한 조각이고(`shortSlots`: `가+(ㄴ)댔+어`, `하+랬+는데`), `냬`(냐고 해)는 맺음 한 조각이다. 사전에 없는 꼴이고 `해` → `했`과 같은 이치로 읽는다.
- 숫자(`addNumbers`, 표는 `number_table.go`). 숫자만으로 된 열은 수다(`수:숫자열`, `3[수]`). 원문자·괄호 숫자(`①`~`⑳`, `㉑`~`㊿`, `⑴`~`⒇`; `enclosedRanges`) 한 글자도 수 원자다(`enclosedAtoms`, `①[수]`, `⑦[수]+의`). `sideOf`는 이 한 글자를 숫자 열과 같게 보아 `①원고`에서 낱말이 끊기고, `units`는 그 뒤에 단위·`째`를 잇는다(`②[수]+번[단위:번]`). `①~③`, `①②`, `①-1`은 읽지 않고, 원 한글·원 로마자는 수가 아니다. 글자가 섞인 열(`L2`, `v1`)은 영숫자 열로 남는다. 소문자 `0x` 뒤에 16진 숫자(0-9, a-f, A-F)가 하나 이상 이어진 열은 수 `수:16진법`이고 한 가지로만 읽으며(`hexRun`, `joinChain`: `0x1234[수:16진법]`, `0xFF`), 그 뒤의 조사·맺음·단위·큰 수·서술격은 숫자 열이 받는 것과 같다(`0x1234면` → `0x1234[수:16진법]+면[맺음:면]`). `0x`만 있는 열, `0x12G4`, `0X1F`는 영숫자 열이다. 숫자만으로 된 열 하나가 0과 1로만 이루어져 있으면(한 글자도) 수 후보에 더해 `수:2진법` 후보를 하나 더 낸다(`numberCandidates`: `1010[수]`, `1010[수:2진법]`. 성립과 선호가 같고 `[수]`가 먼저다. 단위·조사·맺음이 붙어도 두 후보가 다 선다: `10[수:2진법]+개[단위:개]`, `100[수:2진법]+%[단위:%]`). 기호로 이어진 수(`1,000`, `1.01`, `10:10`)와 부호·돈 기호가 붙은 수는 이름을 기호의 그래프가 정한 한 덩어리라 2진법 후보가 없다. 숫자가 하나라도 섞이면(`102`) 없다. 두 숫자 열 사이의 기호 하나(`,` `~` `-` `:` `/` `.`, 그리고 변이 글자 `∼` `～` `〜`는 `~`와, `–`(U+2013)는 `-`와 같은 풀이)는 풀이마다 그래프가 판정하고(예외 `PartsShape`: 같은 기호로 이어진 마디들의 수, 자리 수, 값의 범위, 첫 마디의 머리), 선 풀이가 있으면 열을 한 수로 잇고 그 이름을 단다. 자릿수 `,`는 첫 마디 1~3자리와 그 뒤 3자리씩(`1,000[수]`), 범위 `~`·`-`는 두 마디, 시각 `:`은 1~2자리(0~24):2자리(0~59)에 초까지, 비율 `:`은 두 마디, 날짜 `-`·`.`은 4자리-월(1~12)-일(1~31), 날짜 `/`는 월/일, 나눔 `/`는 두 마디, 전화 `-`는 0으로 시작하는 2~4자리-3~4자리-4자리, IP `.`은 0~255 네 마디다. 겹치는 풀이는 후보가 따로 나온다(`10:30[시각]`과 `10:30[비율]`, `11/10[날짜]`와 `11/10[나눔]`, `2026.11.10[버전]`과 `2026.11.10[날짜]`, `1.2.3.4[버전]`과 `1.2.3.4[IP]`). 후보마다 성립과 선호가 같다. 수의 맨 앞에 선 `-` `+` `$` `₩`는 왼쪽에 글자가 붙지 않았을 때 수에 든다(`-3[부호]`과 `-3[수]`, `$40[돈]`과 `$40[수]`; 단위 가장자리의 이 기호와 수 뒤의 `%`·`℃`는 떼지 않는다, `trimUnit`). 숫자 열 바로 앞의 `제`는 낱말 머리(단위 머리, 기호 뒤)이거나 수의 끝(숫자, 숫자 뒤 단위) 바로 뒤일 때 수에 들고 이름 `차례`가 더해진다(`orderFront`, `numberBefore`: `제1[차례]+항[단위:항]`과 `제1[수]+항[단위:항]`, `제36조│제1항`, `제3조의2│제1항`. 그래프 `차례:제`, 예외는 오른쪽이 수가 아니다·왼쪽에 수의 끝이 아닌 글자가 붙어 있다). 그 밖의 글자 뒤(`문제1`, `같은법제3조`)에서는 들지 않는다. 2진법 후보는 없다. 수 바로 뒤에는 `여`(어림), 단위 표의 낱말, `째`(차례)가 이 차례로 조각으로 선다(`units`, 예외 `PieceIs`, 기준 `PieceNum`에 `Not`): `3[수]+개[단위:개]+를`, `3+번+째`, `10+여`, `20+ms[단위:ms]`. 단위 표(`pkg/data/units.tsv`)는 닫힌 표이고 수 뒤에서만 읽는다. 표의 줄은 글자와 이름이고, 조각 이름은 `단위:<이름>`이다(이름 기준은 `pkg/data/README.md`: 표준 한글 이름, 줄임말 없음, 같은 단위는 글자가 달라도 같은 이름, 한글 단위는 글자가 이름. 글자 하나에 줄이 둘이면 `unitRows`의 줄마다 `addAfter`가 한 번씩 불려 그래프가 둘 서고 후보가 따로 나온다: `5[수]+m[단위:미터]`, `5[수]+m[단위:분]`. 영문·기호 단위는 한글 이름이다: `12[수]+GB[단위:기가바이트]`). 단위 뒤, `째`가 서는 자리에 접미 `짜리`·`가량`·`당`이 선다(`백+원+짜리`, `3+명+당`). 긴 단위와 그것의 앞쪽 짧은 단위는 맞는 자리마다 함께 읽는다(`3+개월`, `3+개 월`). 그 뒤에 조사 사슬과 서술격 이다가 이어진다(`3+개+이+다`). 수와 단위의 그래프는 반박이 없어 성립 1이고, 수 뒤 조각의 선호는 표의 항목 수로 고르게 나눈 값이다(표에 횟수가 없다; 분모는 단위 표의 줄 수 + `afterOthers`이고 글자 수가 아니다. 한 글자에 줄이 둘이면 둘 다 센다). 숫자와 영문 단위가 붙은 열(`12GB`)은 수와 단위 두 열로 갈리는데(`splitUnits`), 가르기 전의 열 전체가 한 줄기인 후보도 `열:영숫자`로 읽는다(`12GB[열:영숫자]`. `scan.wide`에 갈린 열의 시작과 끝을 적어 두고 `atomStem`이 원자가 맞지 않을 때 돌려준다. 낱말 표가 아는 낱말이 먼저다). 영문 단위 글자는 ASCII 영문자 또는 전각 영문자(U+FF21~FF3A, U+FF41~FF5A)로 시작할 수 있다(`isLatinUnit`: `5[수]+ｍ[단위:미터]`, 표에 없는 `ｍｍ`은 영숫자 열). 단위 뒤의 `~`(변이 글자 `∼` `～` `〜`도)는 뒤에 수가 오면 앞 어절을 닫는 조각이다(`1+월+~[범위] 3+월`).
- 단위 앞의 수(`numerals`, 표는 `numeral_table.go`). 규칙은 단위에 있다(예외 `PieceIs`, 기준 `PieceNum`에 `Not`). 수로 치는 것은 숫자 열, 붙여 쓴 한글 수사, 표의 영문 글자다. 고유어 수사는 단위 앞 꼴 한·두·세·네·다섯·여섯·일곱·여덟·아홉(혼자, 또는 `열` 뒤: `열두`), 혼자 서는 열·스무·몇·여러다. 한자어 수사는 일~구와 십·백·천·만·억·조를 글자마다 읽되 일~구 둘이 맞닿지 않는 열이고(`삼십`, `이백`, `삼천오백육십칠`. 길이 한도는 없다), `수`는 맨 앞에서 큰 수 앞에만 선다(`수십`). 영문 글자는 `N` `n` `X` `x` `K` `k`가 그 글자 하나로 열일 때만이다(`N개`; `Nx개`, `L2개`는 아니다). 단위 `목` 앞에서는 차례 글자(가~하, 거~허, `orderLetters`)도 수다(`orderLetter`: 낱말 머리이거나 수의 끝 바로 뒤일 때: `가[수]+목[단위:목]`, `제1[차례]+호 가[수]+목`. 한글 수사처럼 뒤에 글자가 이어지면 기각하고(`다목적`), 글자와 `목`을 합친 글자열이 낱말 표의 낱말이면 통짜 낱말이 먼저 선다(`나목`, `거목`)). 이런 수는 줄기로 `한[수]+개[단위:개]`처럼 찍히고, 선호는 표의 항목 수로 고르게 나눈 값이다. 숫자 열 뒤의 십·백·천·만·억·조는 조각 `큰 수:<꼴>`로 단위 앞에 선다(`7[수]+만[큰 수:만]+장`, `3+천+만+원`, `10+억`). `제`가 붙은 수 뒤에서 단위 표에도 있는 큰 수 글자(`조`)는 반박 `PieceIs`(기준 `PieceOrder`, 힘 `forceWhole`)가 큰 수 풀이를 뒤로 보낸다(`제36[차례]+조[단위:조]`. 큰 수 후보는 지우지 않고 남는다. `제`가 붙지 않은 `36조`는 그대로 큰 수가 앞선다). 한글 수사나 영문 글자 뒤의 단위는 뒤에 글자가 그대로 이어지면 기각한다(예외 `PieceRight`): 조사 사슬, 서술격 이다, `째`가 오거나 거기서 단위(띄어쓰기 사이)가 끝나야 한다(`사회적`의 `회`는 단위가 아니다). 낱말 표가 있을 때 숫자 열 뒤의 단위는 글자가 이어져도 어절을 닫는다(`10+개 언어`). 한 음절 한글 수사와 단위를 합친 글자열이 낱말 표의 낱말이거나 줄임 꼴이면 반박 `PieceIs`(기준 `PieceWhole`)가 단위 풀이를 뒤로 보낸다(`이건`, `세대`, `조건`은 통짜 낱말이 먼저 선다). 낱말 표가 없으면 한자어 한 음절 수사(일~구)는 홀로 수 자리에 서지 못한다(예외 `PieceIs`, 기준 `PieceLone`). 고유어 수(한, 두, 세, 네, 몇 …)는 그대로 받는다. 띄어 쓴 `세 개`는 읽지 않는다.
- 조사 사슬은 "앞 조사의 갈래 → 뒤에 올 수 있는 조사의 갈래" 표(`rule.Links`)로 판정한다. 표준 문법의 일반 규칙이고, 표에 없는 짝은 기각한다(`결+과+가`, `마당+에+서`). 사슬의 길이 한도는 없다: 갈래 표가 허락하는 대로 읽는다(`친구+에게서+부터+는+요`). 조사의 풀이마다 갈래가 따로다(`linkOf`: `에서`의 주격 풀이는 격조사, 부사격 풀이는 부사격). 예외를 더하려면 그 조사 풀이의 그래프에 예외 간선을 얹는다(`markerGraph`). 모음 뒤의 강조 `야`(`에야`)는 이 층만 읽는 `보조사:야`다. 이 층만 읽는 조사는 `ownParticles`에 있다: `은커녕`·`는커녕`(통짜 조사), 부사격 조사 뒤에만 서는 강조의 `가`(`에서+가`, 갈래 `LinkEmph`). 앞 조사의 사슬로만 이어 읽으므로 수 단위 뒤(`3건가`), 높임 뒤, 맺음 뒤(`먹기가`, `먹는지가`)에는 서지 않는다. 줄기 바로 뒤에서 단위를 끝내는 보조사 `이야`·`야`(`leading`)는 그 뒤에서 마침표·물음표·느낌표가 단위를 닫으면 서지 못한다(예외 `PieceIs`, 기준 `PieceClosed`: `문제야.`는 `문제+(이)+야`). 앞말을 내세워 뒤의 서술로 잇는 조사라 문장이 대체로 그것으로 끝나지 않는다. 닫는 부호는 단위의 글자에서 읽는다(`unitScan`, `closes`: 읽는 글자 바로 뒤의 `.` `?` `!`. 이어진 점은 말을 줄인 것이라 닫지 않는다: `나야 뭐...`). 부호가 있는 단위의 끝에서만 그 조사들의 그래프에 그 사실을 넣어 다시 묻고(`onStem`, `groupAt`), 다른 조사 뒤나 맺음 뒤의 `야`는 묻지 않는다(`에서야.`, `하고 나서야.`). 부호 없이 끝난 문장의 마지막 단위는 단위 밖의 사실이라 보지 않는다. 호격 `야`는 앞말이 그래프 `앞말:부르는 말`을 지나야 선다(`calledGate`, 예외 `Listed`: 앞말이 닫힌 집합의 의존명사다. `거야.`는 `거`를 부르는 말이 아니다). 조사의 풀이마다 그래프가 따로여서 앞말 판정도 풀이마다 따로다: 문장 가운데의 `거야`는 `거+야[보조사:야]`로만 서고, 호격 풀이는 앞말 `거`가 부르는 말이 아니라서 서지 못한다. 앞말이 부르는 말이면 두 풀이가 나란히 선다(`철수+야[보조사:야]`, `철수+야[호격:야]`). 연결 어미 지·고·게·어(와 아래의 맺음들) 바로 뒤의 보조사 도·는·만·야는 같은 어절의 조각이다(`보+지+도`, 그래프 `사슬:맺음 뒤 보조사`). 그 짝이 표의 맺음이면(어도, 지만) 그 맺음으로만 읽는다. 묻거나 헤아리는 맺음 ㄴ지·는지·은지·ㄹ지·을지·냐·느냐·는가 바로 뒤의 조사도 같은 어절의 조각이다(`맞+는지+를`, `좋+은지+는`, `가+(ㄹ)지+도`, 그래프 `사슬:물음 맺음 뒤 조사`). 이 맺음으로 닫은 절은 체언처럼 쓰여 보조사 도·는·만·야와 격조사 가·를·에·와를 받는다(`askClosings`, `askParticles`). 예외는 둘이다: 앞의 맺음이 그 여덟이 아니다(`Listed`에 `Not`, 앞 조각의 이름), 조사가 그 여덟 꼴이 아니다(`Listed`에 `Not`, 조각의 꼴). 그 조사 뒤에는 사슬 표가 허락하는 조사가 더 이어진다(`하+(였)+는지+에+는`). 꾸밈 맺음과 `지`로 가른 풀이(`맞+는 지+를`)는 그대로 나란히 선다.
- 받침 없는 말 바로 뒤의 `에`+`요`(`고양이에요`)는 글자가 맺음 `예요`를 `에요`로 잘못 적은 꼴과 같다. 그래서 조사 풀이 `부사격:에`의 그래프에 반박을 하나 건다(`echoes`, `markerGraph`): 주장 "이 `에`는 부사격 조사다"를 `forceClash`로 낮춘다. 사실 `PieceYoOpen`(`rule.Piece.YoOpen`)이 참일 때 걸린다. `에` 바로 뒤가 보조사 `요`이고, 다음 둘 가운데 하나가 참이어야 한다(`yoOpen`): `에`가 줄기 바로 뒤에 서고(사슬의 첫 조각) 그 줄기의 마지막 글자가 받침 없는 한글 음절이다, 또는 `에`가 줄기 위의 접미 `이` 바로 뒤에 선다(글자로 읽는다: `에` 앞이 `이`이고 그 앞 글자에 받침이 있다. 접미 `이`는 받침 뒤 사슬의 맨 앞에만 서고, 접미 `이`로 끝난 말은 `이`로 끝나므로 받침 없는 말 뒤라는 뜻은 같다). 어느 것이 사슬의 첫 조각인지는 사슬을 오른쪽에서 왼쪽으로 읽는 동안에는 모르므로, 뒤에 `요`가 오는 자리의 조사는 줄기 바로 뒤의 후보로 한 번 더 묻는다(`onStem`, `groupAt`의 `onStem`). 후보는 지우지 않고 뒤로 갈 뿐이다(성립 2/(1+0.5)-1, 약 0.33). 낱말 표가 있든 없든 건다(없을 때는 줄기가 새 낱말이라 후보의 성립이 이미 1/3이어서 값이 달라 보이지 않는다). 받침 있는 말 뒤(`집에요`), 서술격 뒤(`학생이에요`의 `이`+`에요`), `아니에요`, 띄어 쓴 `에요` 단위, `에` 뒤가 `요`가 아닌 사슬(`학교에는`, `학교에서요`, `학교에`)에는 걸리지 않는다. `학생+이[접미:이]+에+요`도 이 반박을 받아 성립 0.33으로 내려가고 후보는 남는다. 다른 조사 뒤의 `에`(`에` 앞에 접미 `이` 아닌 조사가 있는 사슬)에는 걸지 않는다.
- 닫힌 집합 낱말(의존명사, 보조 용언, 관형사, 접속 부사)은 열쇠다. 낱말 표가 있을 때 닫힌 집합 낱말이 그 집합의 갈래로 서면 집합의 이름(`수[의존명사:수]`)으로 후보를 내고, 낱말 표에 그 줄기의 갈래가 있고 그 갈래의 그래프도 줄기를 받아들이면 낱말 표의 이름(`수[열쇠:체언]`, `있[열쇠:동사]`, `있[열쇠:형용사]`)으로도 후보를 낸다(`passedCandidates`. 집합의 이름이 먼저, 그다음 `kindOrder` 차례. 같은 갈래의 두 이름은 갈래 그래프의 판정과 갈래의 횟수가 같으므로 성립·선호가 같다). 낱말마다 그래프가 있고, 낱말 표가 없을 때 그 그래프가 판정한다: 그 집합이 뒤에 붙은 것을 받지 않으면 예외 `StemTail`이 꺾는다(보조 용언 줄기는 홀로 서지 못하고, 관형사 뒤에는 선어말·맺음이 붙지 않는다. 조사는 막지 않는다). 관형사 가운데 대명사이기도 한 `이`·`그`·`저`는 조사나 서술격 앞에 서면 이름을 대명사로 붙인다(`pronounName`: `그[대명사:그]+의`. 홀로 서면 `그[관형사:그]`). 표에 없는 토큰 열은 `새 낱말` 그래프가 판정한다(주장에 "열쇠 표에 없다"는 반박이 힘 0.5로 붙어 verdict 1/3). 표지가 붙은 새 낱말 줄기가 ㅆ 받침으로 끝나면 서지 못한다(예외 `StemCoda`, 낱말 표가 있을 때만 그래프에 건다). 단위 안의 경계 뒤에 선 통짜 새 낱말은 그 글자열이 그 자리에서 통째로 표지로 읽히면 서지 못한다(예외 `PieceIs`, 기준 `PieceMarked`: `선생님` 뒤의 `께서`). 글자열이 표지로 읽히는지는 `marked`가 읽고, 서는지는 새 낱말 그래프가 그 사실과 줄기의 꼴, 뒤에 붙은 것, 표가 아는 갈래를 한 번에 받아 판정한다(`unlisted`). 낱말 표가 있으면 그런 글자열은 꼬리가 붙은 새 낱말의 줄기로도 서지 못한다(`마당 에+서`, `것 이+다`). 이음 `으`로 시작해 표지 열로 이어지는 줄기도 그렇다(`으+며`, `으+로`, `으셨+다`). 표가 아는 낱말은 낱말로 선다. 낱말 표가 없으면 줄기에는 걸지 않는다(줄기 `들`과 접미 `들`을 가를 수 없다): 그때는 그 예외를 "뒤에 표지가 붙었다"(`StemTail`)가 다시 꺾게 그래프를 짠다.
- 색인(`index`)은 표지 꼴의 마지막 토큰에서 그 표지들로 간다. 합쳐진 토큰은 토큰 그대로와 받침(ㄴ, ㄹ, ㅁ, ㅂ, ㅆ)·모음(어/아)의 열쇠 양쪽으로 찾는다(`keysAt`). 받침·모음 판정, 붙는 조건, 사슬과 칸의 순서 같은 조건식은 `pkg/rule`의 것을 `nlgeul parse`와 함께 쓴다.

## 스트림 읽기

- 단위는 띄어쓰기 사이다. 단위 앞뒤의 기호는 읽는 글자에서 떼어 따로 올린다(아래 "가장자리 기호"). 문장을 단위로 가르는 단계(`unitsOf`, `cutter`)는 문장을 앞에서부터 훑으며 여닫는 기호에서도 가르고(아래 "여닫는 기호"), 글자 사이의 `+`에서도 가른다(아래 "기호와 영문·숫자 열"). 뒤를 보고 짝을 맞추지 않는다. 백틱 사이의 코드만 두 개씩 묶어 안의 띄어쓰기째 한 조각으로 두고 읽지 않는다(`` `a b`[코드]+를 ``). 단위를 읽을 때는 단위 밖을 보지 않는다.
- 토큰 자리마다 거기서 끝나는 표지 열을 색인에서 찾아 그래프를 돌린다(`tailsAt`: 조사 사슬 `chains`, 선어말 칸 `slots`, 맺음 `closings`). 기각된 것은 버린다.
- 후보(`path`)는 어절의 연쇄다. 어절은 줄기(새 낱말 또는 열쇠)와 그 뒤 표지들이다. 표지 없는 어절은 닫힌 집합 낱말이거나 단위의 끝에서만 선다.
- 성립은 조각 verdict의 최솟값, 선호는 조각마다 log10(관측 횟수 ÷ 표의 총 횟수)의 합이다. 횟수가 없는 표지와 줄기는 음절마다 log10(1/11172)로 친다. 표지의 횟수는 이 층만 읽는 표(`counts_table.go`, 값은 `pkg/data/closing-counts.tsv`와 `particle-counts.tsv`)에 꼴마다 따로 있고(이형태 짝 이/가, 을/를, 면/으면도 저마다의 횟수. 다만 세요/으세요, 십시오/으십시오, 어다가의 세 꼴, ㄴ들/은들, ㅂ시다/읍시다, ㄹ뿐더러/을뿐더러, 이라고/라고, 아/야, 이시여/시여, 이든가/든가는 한 값을 함께 쓴다. 횟수의 출처와 확보일은 이 저장소에 기록이 없다), 합에는 같은 꼴을 풀이가 몇이든 한 번만 더한다. `nlgeul parse`가 읽는 문법 표의 횟수 칸은 그대로다. 합쳐진 어/아와 ㅆ은 풀어 쓴 꼴(아, 었)의 횟수로 친다. 후보의 수에는 한도가 없다: 그래프가 기각한 후보 말고는 모두 올린다(`top`은 후보를 나은 것부터 세우고 글줄이 같은 후보를 한 번만 둔다). 자리마다 남기는 후보를 줄이지 않고, 끝에 닿은 후보도 단위 전체를 앞 단위에 붙는 표지로 읽은 풀이와 합쳐 나은 것부터 모두 올린다. 어떤 후보도 다른 후보들 사이의 자리 때문에 빠지지 않는다.
- 줄기 끝 음절에 조각이 합쳐진 후보는 줄기를 본디 꼴로 되돌려 찍고(열쇠도 그 꼴로 찾는다), 합쳐져 있던 조각은 괄호에 본디 꼴로 적는다: `마시+(ㄴ)다`, `하+(ㅂ)니다`, `가+(았)+다`, `하+(여)서`, `쓰+(어)`(`restores`, `fusedTails`). ㅏ·ㅓ는 같은 모음의 줄기와 ㅡ가 빠진 줄기 두 갈래로 올린다(`써` → `써+(어)`, `쓰+(어)`). ㅡ가 빠진 줄기는 낱말 표가 르·러 불규칙으로 적은 줄기가 아니고 어/아가 ㅡ 앞 음절의 모음에 맞을 때만 선다(그래프 `줄기:되돌린 끝 음절`의 예외들, `restored`: `따르+(아)`, `치르+(어)`는 서고 `모라`를 `모르+(아)`로 읽지 않는다. 한 음절 줄기는 어뿐이다). 줄기 끝 `하` 뒤의 어/아는 여이고 `해`·`하여`로 글자에 드러나므로, 글자 그대로인 `하` 뒤에는 글자 없는 어/아를 읽지 않는다(`하지는`·`말하지는`을 `하+(아)+지+는`으로 읽지 않는다. 같은 그래프의 예외 "하 뒤의 어/아는 여이고 글자에 드러난다"(`Listed`, 닫힌 표 `yeoBases`)를 "합쳐진 조각이 글자에 흔적을 남겼다"(`PieceSame`에 `Not`. `restored`가 넣는다)가 다시 꺾으므로 `해`의 `하+(여)`는 서고, `가서`의 `가+(아)`도 그대로다). `놔`는 `놓+(아)`로도, 낱말 표가 있으면 `마`는 `말+(아)`로도 되돌린다(`하지 마`, `마라`). 줄기 끝 음절 `되` 뒤에서는 글자에 없는 어도 읽는다(`unspelt`, `unspeltAt`: `되+(어)도`, `되+(어)서`, `되+(어)야`, `되+(어)+요`, `되+(었)+다`). `돼도`, `돼서`, `됐다`로 적어야 하는 꼴(한글 맞춤법 제35항 붙임 2)을 `되도`, `되서`, `됬다`로 적은 것이고, 가·서·내·세처럼 겉으로 안 바뀌는 합침과 같은 자리에서 같은 값으로 읽는다(홀로 선 `(어)`는 흔적 없는 조각의 값을 치른다). `되+도[보조사:도]` 같은 다른 풀이는 그대로 선다. 영문·숫자 바로 뒤의 음절에서는 조각을 떼지 않는다(같은 그래프의 예외 `PieceAfter`. 하·되·이는 뗀다: `push하+(여)`, `latinBases`). 겉으로 안 바뀌는 모음 합침(가, 서, 내, 세)은 뒤에 조각이 더 있거나 단위의 끝이거나 바로 뒤가 보조 용언 줄기일 때만 읽는다(`가보다` → `가+(아) 보+다`). 보조 용언 줄기의 끝 음절에 조각이 합쳐진 글자여도 된다(`auxHead`: `빼줘` → `빼+(어) 주+(어)`, `가볼까`). 낱말 표가 있으면 합쳐진 어/아와 았/었은 흔적이 있든 없든 앞말이 표의 용언 줄기일 때만 선다(`asksStem`, 그래프 `앞말:용언`. 해·했은 묻지 않는다). ㅕ는 ㅣ+어(`마셔` = 마시)와, 낱말 표가 있으면 줄기 자신의 ㅕ+어(`켜` = 켜)로 푼다. `--cuts`의 자리는 원문 토큰 자리 그대로다.
- 맺음은 parse와 함께 쓰는 맺음 표에, 이 층만 읽는 표(`moreClosings`, 값은 `pkg/data/closings-more.tsv`)를 더해 읽는다: 사전에 어미로 올라 있는 되, 어야지, 어야만, 어다가, 다면서·다며·다니 무리, 길래, 든가, ㄴ들, ㄹ망정, ㄹ지라도, ㄹ뿐더러, ㄹ세라, 으라고, 다만, 건만, 건대, 느냐고, ㄴ지라, 인용이 줄어든 냐는·느냐는·자는·냐며·냐면·냐면서·냐니까·자면·자니·자니까·다니까·라니까·다더라 무리, 답니다 무리, 사전에 줄어든 말로 오른 려는·려던(려고 하는·하던), 그리고 표 끝에 더한 사전의 어미 거라·너라·렴(으렴)(동사만), 하소서체 나이다·나이까·더이다·소서(으소서, 동사만), 하오체 오리다(으오리다), 노라고·노라면(동사만), 거니와, 던지, 다거나, 서술격 뒤의 로구나·로다(서술격만), ㄴ걸이다. 이 줄들은 `closing-counts.tsv`에 횟수가 없다(관측값이 없어 적지 않았다). 너라는 사전에서 오다 뒤에만 서지만 표는 줄기를 가리지 않는다. 낱말 표가 있으면 표의 용언 줄기 뒤에서 이름 꼴 맺음 기도 읽고(`gatedClosings`), 하오체 맺음 소·오·으오·올시다도 같은 자리에서 읽고(`haoClosings`: `먹+소`, `가+오`, `받+으오`, `아니+올시다`. `소`·`오`는 낱말 끝에 흔한 글자라 표 줄이 아니라 이 목록으로 두고, 이름 꼴 목록 `gatedClosings`와 따로 둔다. 받침 없는 줄기 뒤 `오`와 ㄹ 아닌 받침 뒤 `으오`는 줄을 나눴고 ㄹ이 빠진 `노오`는 읽지 않는다. 이다 뒤 `오`는 서술격 쪽에서 읽혀 `책+이+오`가 된다), 그 바로 뒤의 조사 사슬을 같은 어절의 조각으로 읽는다(그래프 `사슬:이름 꼴 뒤 조사`: `있+기+는`, `받+기+에+는`). 맺음 표의 이름 꼴 맺음 `음`·`ㅁ` 뒤의 조사 사슬도 같은 그래프로 읽는다(`있+음+을`, `되+(ㅁ)+을`, `것+이+(ㅁ)+을`, `하+였+음+으로써`). 줄기와 `ㅁ`이 한 음절에 합쳐져 조사 바로 앞에 선 꼴(`됨을`, `함을`)도 읽는다. 목록은 `chainHeads`이고 빠진 이의 목록(`droppableKnown`, `dropAdn`, `dropNaming`)은 `기`만이다. 맺음 바로 뒤의 보조사(도·는·만·야)는 지·고·게·어/아와 어서·아서·면서, 인용 맺음 다고·라고·자고·냐고·느냐고, 연결 어미 다가·고서·려고(으려고) 뒤에서 읽는다(`먹+어서+는`, `좋+다고+만`, `하+였+다가+도`, `하+고서+야`). 는데·ㄴ데·은데 뒤에는 넣지 않았다(정답지 평가에서 고침 0, 망침 3: 정답지가 셋 다 꾸밈 맺음+의존명사 데로 적음). 용언 줄기에만 붙는 맺음 은·는·을(꾸밈)과 아·어·나·여는 앞 글자가 한글 음절이 아니면(영숫자 열, 수, 코드, 경로, 파일명) 읽지 않는다(`push는`은 `push+는[보조사:는]`, `API을`은 `API+을[목적격:을]`). 그 맺음 그래프의 예외 "앞 글자가 한글 음절이 아니다"(`PieceAfter`, `hangulBound`)가 꺾는다: 영숫자 열로 된 용언은 `하`나 서술격 `이`를 사이에 둔다(`push하+는`, `API+이+(ㄴ)`). 이가 빠질 수 있는 다·고·면·지·네는 건드리지 않는다.
- 의존명사 집합에는 띄어쓰기 표의 의존 명사에서 옮긴 낱말(간; 외, 적, 채; 시, 듯, 만. `pkg/data/README.md`)도 든다. 낱말 표가 그 낱말을 명사로도 적으면 두 이름의 후보가 같은 성립·선호로 나란히 선다(`간[의존명사:간]+에[부사격:에]`와 `간[열쇠:체언]+에[부사격:에]`). 집합의 다른 의존명사처럼 호격 `야` 앞에서 불리는 말이 아니다(`calledGate`).
- 낱말 표가 있을 때 새 낱말 줄기가 서지 못하는 곳: 표지 꼴 줄기(`marked`. 받침을 뗀 `으`도 이음 으로 본다: `으+(ㄹ)걸`), 표나 닫힌 집합이 용언 아닌 갈래로만 아는 낱말이 서술어 꼬리 앞에 선 것(새 낱말 그래프의 예외 `StemKind`. "표에서 용언 줄기이기도 하다"와 "뒤가 서술어 꼬리가 아니다"가 그 예외를 꺾는다: `뭐+냐`, `거+네`). 경계 뒤의 통짜 새 낱말은 글자열이 표지 한 열이나 표지 두 열의 이음으로 읽히면 서지 못한다(`twoRuns`: `는게`). 줄기 안에서 영문 글자 바로 뒤에 글자 갈래가 바뀌는 자리(`change`. 숫자 뒤 자리는 묻지 않는다)가 있고, 줄기 머리부터 그 자리까지가 원자 하나이며, 그 자리부터 낱말 끝까지의 글자가 「한글 맞춤법」 제48항의 호칭어·관직명(`호칭·관직`)이나 제42항의 의존 명사(`의존 명사(체언 뒤)`) 하나로만 읽히는 새 낱말도 서지 못한다(새 낱말 그래프의 예외 `PieceIs`, 기준 `PieceApart`. `writtenApart`, `apartWord`: `A씨+가` 대신 `A` │ `씨+가`, `B군`, `PD님`). "하나로만"은 꼬리 없이와 그 자리에서 끝나는 꼬리마다 아는 낱말로 읽은 줄기가 모두 한 자리에서 끝나고, 그 줄기 글자가 두 집합에 있으며, 어느 읽기도 동사·형용사가 아니라는 것이다. 같은 글자가 다른 체언이나 용언으로도 읽히면(`C양의`, `OO내는`) 조항이 둘 사이를 정해 주지 않으므로 남긴다. 이 예외는 낱말 표 유무와 상관없이 그래프에 걸지만, 낱말 표가 없으면 그 낱말을 아는 읽기가 거의 없어 서지 않는다. `--spacing`의 조항 스위치에 묶지 않는다. 영숫자 열과 한글이 맞닿은 자리(`change`. 영숫자가 앞이든 한글이 앞이든, 숫자 열도 영숫자 열이다)를 줄기 안에서 넘고, 그 자리에서 가른 두 쪽이 모두 아는 낱말이나 영숫자 열로 읽히는 통짜 새 낱말도 서지 못한다(새 낱말 그래프의 예외 `PieceIs`, 기준 `PieceChange`. `crossesChange`, `readsKnown`: `A씨+가` 대신 `A` │ `씨+가`, `K팝`, `학교A`). 조각이 합쳐진 줄기 끝 음절 바로 앞 자리도 줄기 안의 자리다(`git했다`의 `git하`). 앞쪽은 원자 하나이거나 꼬리 없는 아는 낱말이고, 뒤쪽은 꼬리 없이나 낱말 끝에서 끝나는 꼬리마다 아는 낱말·원자·그 밖의 성립이 0보다 큰 후보로 읽히면 된다(새 낱말 후보는 치지 않는다. 갈래는 가리지 않는다). 이 예외는 낱말 표 유무와 상관없이 그래프에 걸지만, 낱말 표가 없으면 아는 낱말이 닫힌 집합뿐이라 덜 선다. `--spacing`의 조항 스위치에 묶지 않는다. 이 예외가 지우는 것은 통짜 새 낱말 후보뿐이다: 표지 없는 낱말을 세우는 `wholeAt`은 표에 없는 글자열을 어느 읽기로든 세울지를 이 사실을 뺀 새 낱말 판정(`unlistedPiece`)으로 묻고, 이 예외로만 서지 못하는 새 낱말은 그 읽기 하나만 빼므로 같은 글자열의 다른 읽기는 남는다(닫힌 집합의 `제`와 원자 `1-1` 사이 자리를 넘는 `제1-1`: `제1-1[차례]`, `제1-1[범위]`).
- 낱말 표가 있을 때 새 낱말 줄기는 ㅆ 받침으로 끝나지 못한다(새 낱말 그래프의 예외 `StemCoda`): 표에 없는 줄기에 표지(조사, 선어말, 맺음)가 붙은 후보에서 줄기의 마지막 음절이 ㅆ 받침이면 서지 못한다(`떨어졌+다`, `떨+어 졌+다`). ㅆ 받침으로 끝나는 줄기는 `있`과 그것으로 된 낱말뿐이고(낱말 표에 있다) 나머지 ㅆ은 선어말 았·었·겠이다. 줄기는 조각이 합쳐지기 전의 꼴로 본다. 표지 없는 통짜 새 낱말(`떨어졌다`)과 표가 아는 줄기(`있+다`)는 그대로 선다.
- 낱말 표가 있을 때 꾸밈꼴 바로 뒤에 용언이 오지 못한다(`afterAdn`, 갈래 그래프 `열쇠:동사`·`열쇠:형용사`의 예외 `PieceIs`, 기준 `PieceAdn`): 한 단위 안에서 꾸밈 맺음으로 끝난 낱말 바로 다음 낱말이 낱말 표의 동사·형용사 줄기로 읽히면 그 후보는 서지 못한다(`떨+(ㄹ) 어지+(었)+다`). 의존 명사에 하다·싶다가 붙은 보조 용언의 줄기(`boundAux`: 듯하, 듯싶, 만하, 법하, 뻔하, 성싶, 성부르, 성하, 척하, 체하, 양하)는 그 예외를 다시 꺾는 예외 `Listed`로 선다(`아+는 척하+(였)+다`). 그 낱말 자신이 꾸밈꼴·이름꼴이면 예외 `PieceIs`(기준 `PieceTurned`, 사실은 `namesForm`이 읽는다)가 같은 예외를 꺾는다. 다음 낱말이 새 낱말, 체언, 관형사, 부사이면 걸리는 예외가 없다. 꾸밈꼴이 앞에 섰는지는 후보마다 다른 사실이라, 꾸밈꼴이 끝나는 자리에서 그 사실을 넣어 갈래 그래프에 다시 묻고 마지막 어절이 꾸밈꼴인 후보에만 그 답을 쓴다. 단위를 넘어선 이웃은 보지 않는다. 갈래 그래프가 줄기를 판정하는 둘째 겹부터다. 관형사 바로 뒤에도 용언이 오지 못한다(같은 두 그래프의 예외 `PieceIs`, 기준 `PieceDet`): 한 단위 안에서 표지 없이 선 낱말의 후보가 관형사이고(`determiner`: `이[관형사:이]`, `세[열쇠:관형사]`. 같은 낱말의 `열쇠:체언` 후보는 관형사가 아니다) 바로 다음 낱말이 낱말 표의 동사·형용사 줄기나 보조 용언 줄기로 읽히면 그 후보는 서지 못한다(`세 보+(아)`). 그 낱말 자신이 꾸밈꼴·이름꼴이면 선다(`어떤 마시+는`, 예외 `PieceTurned`). 의존 명사에 하다·싶다가 붙은 보조 용언은 꾸밈꼴 뒤에만 붙으므로 관형사 뒤에서는 꺾지 않는다. 홀로만 서는 낱말(감탄사 들, 그래프 `열쇠:홀로`)은 꾸밈 맺음으로 끝난 낱말 바로 뒤에도 관형사 바로 뒤에도 서지 못한다(`aloneExcept`, 예외 둘이고 꺾는 것이 없다. 표지 없는 낱말을 세우는 `whole`이 같은 `afterAdn`으로 묻는다). 체언을 꾸미는 말 뒤에는 체언이나 그 체언을 꾸미는 다른 말이 오고, 감탄사는 둘 다 아니다. 부사는 뒤의 관형사·꾸밈꼴을 꾸밀 수 있어 막지 않는다.
- 대명사 네·내·제·니는 이 층의 표(`pronounWords`)에 있고, 낱말 표가 있으면 체언 갈래로 친다(`네+가`, `니+가`). 니는 네·너를 구어로 이르는 꼴이다(`니가`, `니 거`, `니도`). 사전에는 니가 조사·어미로만 있고 낱말 표에도 줄이 없어서, 체언 니에는 관측 횟수가 없다(반박 "관측이 적다"가 걸리지 않고 선호는 횟수 없는 줄기의 값이다). 맺음 니(`먹+었+니`)와 체언 뒤 서술격의 니(`사과+(이)+니`)는 그대로 앞선다: 단위 안에서 다른 낱말 뒤에 선 니는 반박 "한 음절이다"를 받는다.
- 단위 전체가 조사 사슬이나 서술격의 꼬리이면 앞 단위에 붙는 표지로 읽은 풀이를 하나 세운다(`attached`, `loneOf`: `+로[부사격:로]`, `+이[서술격:이]+(ㄴ)데[맺음:ㄴ데]`). 줄기 없는 어절이고 `Attach`가 참이다. 꾸밈 꼴 뒤에서 띄어 쓴 게·건·걸은 `거+(이)`로 읽는다. 띄어 쓴 `테니까`, `텐데`도 `터+(이)+니까`로 읽는다(단위의 머리가 그 글자이고 나머지가 그 뒤의 꼬리일 때). 줄기가 이 단위에 없으므로 성립은 새 낱말보다 높지 않고, 낱말이기도 한 글자(이, 가, 만)는 그 낱말 풀이와 경합한다.
- 남은 후보가 모두 합의한 자리에서 끊는다(`agreed`). 끊긴 구간마다 후보가 하나면 확정, 여럿이면 후보가 둘 이상인 경합이다(`contests`).

- 본용언의 어/아 꼴 바로 뒤에 붙여 쓴 보조 용언 줄기(닫힌 집합의 주·보·버리·놓·두·있, 낱말 표가 있으면 가·내·드리도)는 그 사이 경계의 값을 돌려받는다(`grow`). 그 줄기 뒤가 서술어 꼬리(선어말·맺음)일 때만이다: 같은 글자가 체언으로 서서 조사를 받으면(`주+는[보조사:는]`) 돌려받지 않는다. 그 자리(줄기가 단위의 첫머리가 아니고, 그 보조 용언 줄기이며(합쳐진 조각이 있으면 되돌린 꼴: `줘` → `주`), 뒤가 서술어 꼬리이고, 어느 후보에서든 그 줄기 바로 앞에서 끝나는 낱말이 어/아 맺음으로 끝난다)에서는 줄기의 갈래 그래프에 그 사실을 알리고(`auxAfterConn`, `PieceConn`), 그래프가 반박 "한 음절이다"를 걷는다(아래 "낱말 표"의 2). 앞 낱말은 스트림 마디 값이 기댈 수 없어서 `afterAdn`처럼 어느 후보에서든 그 자리에서 끝나는가로 본다(`connEnds`: `growWord`가, 여닫는 기호 뒤 글자를 읽는 그물에서는 `planter.at`이 적는다). `지`(어지다)와 `하`(어하다)는 늘 붙여 쓰므로 경계를 세우지 않고 같은 어절의 조각으로 읽는다(`helped`: `지우+(어)+지+(ㄴ)다`, `예쁘+(어)+하+(ㄴ)다`). 낱말 표가 있고 본용언이 표의 용언 줄기일 때만이다.

`--trace`는 걸린 토큰 열, 그래프, verdict, 기각 이유를 찍고, `--cuts`는 측정용으로 후보마다 어절 끝 자리만 찍는다.

## 띄어쓰기 규칙

「한글 맞춤법」의 띄어쓰기 조항(제2항, 제41~50항과 다만)을 규칙으로 넣는다. 목적은 띄어쓰기를 바로잡는 것이 아니라 붙여 쓴 덩어리를 어절로 가르는 것이다. 표준이 붙여 써도 된다고 한 자리도 일단 띄는 자리로 본다. 조항은 번호로만 부른다(`SpacingArticles`: `2`, `41`, `42`, `43`, `43다만`, `44`, `45`, `46`, `47`, `47다만`, `48`, `48다만`, `49`, `50`). `Options.Spacing`에 켤 조항의 이름을 준다(비면 모두 꺼서 조항이 없던 때와 출력이 바이트까지 같다. 모르는 이름은 `New`가 오류로 돌려준다). 명령은 `--spacing`(기본 `all`, `none`, 또는 쉼표로 이은 이름)이다. 상자 출력, `--cuts`, 스트림 모두 같은 탐색을 쓰므로 `--spacing`이 함께 든다.

규칙은 세 길로 든다. 값을 매기는 코드(`stepOf`, `structure`, `grow` 들)와 경계 비용은 바꾸지 않는다(48의 읽기가 더한 성 후보의 선호만 `stepOf`가 음절 값으로 친다). 규칙이 낸 끊는 꼴에도 경계마다 경계 비용이 한 번씩 든다.

- 표시(`spacingOf`, `fits…`): 탐색이 낸 후보에서 이웃한 두 낱말(`gap`)을 보고 그 경계가 어느 조항의 자리인지 이름을 붙인다. 후보를 더하지도 빼지도 않는다. 조항마다 판정 함수가 하나다(`fitsAny` 2, `fitsParticle` 41, `fitsBound` 42, `fitsUnit` 43, `fitsUnitDigit` 43다만, `fitsMyriad` 44, `fitsLink` 45, `fitsShort` 46, `fitsAux` 47, `fitsAuxApart` 47다만, `fitsTitle` 48, `fitsSurname` 48다만, `fitsNames` 49·50). 판정은 후보의 두 낱말마다 하고, 같은 자리가 후보에 따라 다른 조항으로 표시될 수 있다. `Reader.Marks`와 `--marks`가 측정용으로 찍는다(`marksOf`: 후보마다 낱말 끝 자리를 `,`로 잇고, 단위 안쪽 끝 자리 뒤에 `:`와 조항 이름을 `/`로 이은 것, 없으면 `-`. 후보 사이는 `;`). 갈래·마디·후보 구조에는 표시를 싣지 않는다.
- 신호(`findCues`): 42, 43, 44, 45, 48은 낱말 표에 없는 낱말 바로 뒤에 선 닫힌 목록 낱말(`pkg/data/spacing-words.tsv`)이나 수의 꼴에서 경계를 알아본다. 그러면 표에 없는 맨 낱말이 거기서 끝날 수 있다. 목록 낱말이 서는 자리(`stands`, `stood`), 그 낱말이 줄기인 낱말 앞에서 끝난 맨 새 낱말을 이을 수 있는 자리(`shows`, `keptBefore`)가 `scan`에 선다. 줄기가 꼭 그 목록 낱말인 낱말만 맨 새 낱말 뒤에 서고, 글자 바로 앞이 한글 음절일 때만 앞을 보인다. 성 목록(48다만)과 꾸밈꼴 뒤 의존 명사, 보조 용언 목록은 세우지 않는다. 꾸밈꼴 뒤 의존 명사와 보조 용언 목록은 표시에만 쓰고, 성 목록은 표시와 아래 읽기(48)에 쓴다.
- 읽기(48, `surnameCandidate`): 48이 켜져 있으면 표지 없는 낱말(합친 조각·틀린 꼴·보인 낱말·수 이름이 없는 꼬리)의 줄기가 단위의 첫 글자에서 시작하는 성 목록 낱말(두 글자 성 `남궁`·`황보` 들도)이고, 바로 뒤에 호칭·관직 목록 낱말이 서고 그 뒤가 단위 끝이거나 조사일 때(`titleAfter`, `right`) 그 줄기를 성으로 읽는 후보 하나를 더한다(`stepsOf`). 줄기의 다른 후보는 그대로 둔다. 이름은 `성:<글자>`(`김[성:김] │ 군[열쇠:체언]+은[보조사:은]`), 갈래는 체언, 성립은 성 그래프(`addSurname`: 성 모두에 그래프 하나, 반박 없음)의 1이고, 선호는 새 낱말처럼 음절 값(토큰마다 log10(1/11172))이다. 낱말 표에 같은 글자가 있어도 그 횟수는 쓰지 않는다(`김`·`이`의 횟수는 성이 아닌 같은 글자 낱말의 횟수다). 단위 가운데에서 시작하는 성과, 호칭 뒤에 조사가 아닌 글자가 이어진 꼴(`김양식장에`의 `양` 뒤 `식`)은 읽지 않는다. 48이 꺼져 있으면 후보를 더하지 않는다.

## 기호와 영문·숫자 열

낱말 표와 무관한 구조 규칙이다(낱말 표가 없어도 적용한다).

- 라틴 문자, 숫자, 밑줄이 이어진 열은 조각 하나다(`runsOf`). 그 안에서는 어절이 시작하거나 끝나지 않고, 그 안의 부분 문자열로 낱말을 찾지 않는다. 표에 없는 열은 `열:영숫자` 그래프가 판정한다(주장에 "열쇠 표에 없다"는 반박이 힘 0.25로 붙어 verdict 0.6, 자리 채움 값). 열 뒤에 한글 표지가 붙는다(`L2+의`).
- `.`은 풀이마다 그래프가 있다(`dotGraph`). 양쪽이 열인 점을 잇는 풀이 넷과, 앞 어절을 닫는 풀이 둘이다.

| 그래프 | 주장 | 예외 |
|---|---|---|
| `파일명:.` | 이름과 확장자를 잇는다 | 양쪽이 영숫자 열이 아니다, 오른쪽이 확장자 목록(`extensions`)에 없다 |
| `도메인:.` | 도메인의 마디를 잇는다 | 양쪽이 영숫자 열이 아니다, 맨 오른쪽 마디가 최상위 도메인 목록(`topDomains`)에 없다 |
| `소수점:.` | 수의 소수점이다 | 양쪽이 숫자가 아니다, 숫자 마디 둘이 아니다 |
| `버전:.` | 버전 번호의 마디를 잇는다 | 양쪽이 영숫자 열이 아니다, 마디가 모두 숫자(첫 마디는 v로 시작해도 됨)가 아니다. 점이 하나인 수는 소수점과 버전의 경합이다(`1.2[소수점]`과 `1.2[버전]`) |
| `마침표` | 문장이 끝났다 | 양쪽이 영숫자 열이다(`MarkBoth`), 점이 이어진다 |
| `줄임표` | 말을 줄였다 | 점이 하나뿐이다 |
| `마침표`(수 바로 뒤) | 수 바로 뒤의 점이 그 수에 딸린다, 뒤에 조사 사슬이 붙는다 | 바로 앞이 수가 아니다 |

- 잇는 풀이가 하나라도 서면 양쪽 열이 한 덩어리(`atom`)가 되고 줄기 뒤 대괄호에 선 풀이가 적힌다(`v1.2.3[버전]`). 둘 이상 서면 풀이마다 후보가 따로 나온다(`task.py[파일명]+에`와 `task.py[도메인]+에`). 후보마다 성립과 선호가 같다. 고를 근거가 없어 고르지 않는다.
- 닫는 풀이는 단위 안에서 앞 어절의 마지막 조각이 된다(`했+다[맺음:다]+.[마침표]`, `stopAt`). 단위 안의 쉼표 하나와 줄임표 `…`(하나든 여럿이든, `...`와 같은 부호)도 같은 길로 앞 어절을 닫는 조각으로 읽고(`stopSigns`), 그 기호를 낱말 속 글자로 둔 후보는 그대로 남는다(`가+,[쉼표] 나`와 `가,나`, `올랐다+…[줄임표] 그래서`). 단위의 끝에 붙은 점은 가장자리 기호로 단위의 경합들 뒤에 제 경합(상자 하나)으로 나온다(`.[마침표]`, `...[줄임표]`). 수 바로 뒤의 점에 조사가 붙으면 그 점은 수의 어절 안 조각이다(`numberStop`): `31[수]+.[마침표]+까지[보조사:까지]`. 조사 사슬만이고 서술격 이다(`1.이다`)와 단위(`3.개`)는 넣지 않는다. 문장부호의 이름표에는 글자를 되풀이해 적지 않는다.
- 두 영숫자 열 사이의 빗금과 붙임표는 이름을 잇는다(`nameSigns`: `a/b[경로]`, `h-Cat[붙임]`). 양쪽이 숫자면 수의 기호다(`11/10[날짜]`과 `11/10[나눔]`, `10-20[범위]`과 `10-20[빼기]`). 아는 낱말 사이의 빗금과 붙임표는 그 낱말들을 한 줄기로 묶는다(`bound`: `입력/출력[대비:/]`, `원-달러[붙임:-]+를`). 낱말 표가 있고 마디가 모두 아는 낱말이거나 영숫자 열일 때만이다. 묶인 줄기의 선호는 마디마다 따로 쳐서 더한다(`partsPref`. 영숫자 열 마디는 토큰 하나다). 원자 하나인 줄기(`a/b[경로]`, `h-Cat[붙임]`)는 마디로 쪼개지 않고 토큰 하나로 친다.
- 문장의 낱말이 아닌 입력으로 시작하는 단위는 그 부분이 조각 하나다(`special`, `wholeAtom`): 주소(`http://`, `https://`), 전자우편, 경로(머리가 `/`·`~/`·`./`·`../`이거나 이름 사이 빗금이 둘 이상), 명령의 옵션(`-x`, `--xx`). 한글이 아닌 마지막 글자까지가 그 조각이고 안에서 낱말을 찾지 않는다. 뒤에 조사가 붙는다(`~/a/b[경로]+를`, `--xx[옵션]`).
- 단위 앞뒤의 기호 가운데 이름에 드는 것은 떼지 않는다(`trimmed`, `headKept`): 경로의 머리와 끝의 빗금, 옵션의 붙임표, 영문 앞의 `$` `_` `.`(`$HOME`, `.env`), 수 맨 앞의 부호와 돈 기호, 수 뒤의 `%`·`℃`. `@`와 `#`는 떼어 가장자리 기호로 읽는다.
- 한글과 영문·숫자 열이 맞닿은 자리는 표지가 없어도 어절이 끝날 수 있는 자리다(`change`): `toulmin엔진` → `toulmin` / `엔진`. 영문 글자 뒤의 이 자리를 넘어 띄어 쓸 호칭어·의존 명사 하나로만 읽히는 글자가 붙은 통짜 새 낱말은 서지 못한다(`writtenApart`: `A씨`). 이 자리를 넘고 그 자리에서 가른 두 쪽이 모두 아는 낱말이나 영숫자 열로 읽히는 통짜 새 낱말도 서지 못한다(`crossesChange`: `A씨`).
- 선호를 셀 때 한 덩어리는 토큰 하나로 친다(`tokens`).
- **단위 안의 기호를 제 어절로 읽는 길.** 글자 사이에 낀 기호(`apartSigns`: 가운뎃점 `·` `ㆍ` `・`과 변이 글자 `‧` `․` `•`, 빗금 `/`, 물결표 `~`와 변이 글자 `∼` `～` `〜`, 줄표 `―` `—`)는 낱말 속 글자로 본 지금의 후보를 모두 두고, 그 기호를 조각 하나짜리 제 어절로 읽는 후보를 더한다(`prepare`가 `findMid`로 자리를 찾아 `scan.mid`에 둔다. 기호 그래프가 판정한다: `가운뎃점`의 예외는 "같은 기호가 이어진다" 하나, `빗금`과 `물결표`는 양쪽이 한글일 때만 서고(`압박골절 /[빗금] 가로돌기골절+로`, `여름 ~[물결표] 가을`), `줄표`는 예외가 없어 이어진 줄표도 한 조각이다(`답+이+다 ―[줄표] 누구+나`)). 경로·주소·옵션 안(`sc.inside`)과 원자(`a/b[경로]`, 수의 `11/10`, 수와 단위 뒤의 `1+월+~[범위]`)는 건너뛴다. 아는 낱말끼리 빗금으로 묶은 후보(`입력/출력[대비:/]`)는 그대로 남아 제 어절 읽기와 겨룬다. 괘선 `─`(U+2500)는 줄표가 아니다. 앞 낱말은 기호 앞에서 끝나고(`keptAt`: 그 자리에 남은 후보에, 기호가 경계를 보여 주므로 표지 없이 끝나는 낱말을 한 번 더해 `whole`의 `shown`으로 만든다. `best`에는 넣지 않는다) 뒤 글자는 새 낱말로 시작한다. 뒤에 표지가 붙지 않는다(`signWords`: 성립 1, 선호 0, 가장자리 기호와 같다. 단위 안 경계의 값은 뒤 낱말이 치른다). 읽는 동안 이 어절의 줄기 이름은 자리 채움 `기호`이고, 경합을 만든 뒤 `expandMid`가 어절의 끝 자리로 기호를 찾아 후보의 조각(`·[가운뎃점]`)으로 바꾼다. 단위 머리 바로 뒤의 자리는 찾지 않는다. `ㆍ`(U+318D)는 유니코드에서 글자라 `rule.Trim`이 떼지 않으므로 단위 가장자리는 `trimSigns`(문장부호·기호와 `signs.tsv`에 이름이 있는 글자)로 뗀다. 가운뎃점은 가르는 후보를 후보로 더할 뿐 이 층은 가운뎃점이 나열인지 셈인지 정하지 않는다.
- **`+`는 단위를 자른다.** 글자 사이(바로 앞과 바로 뒤에 글자가 있다)의 `+`는 자르는 단계(`cutter.cuts`, `cutSigns`)가 그래프 `더하기`·`연결`(예외: 같은 기호가 이어진다, 다른 기호와 맞닿아 있다 `MarkBySign`)를 돌려 후보가 서면 거기서 자르고 `+` 하나를 단위로 낸다(`곰+솔` → `곰`, `+`, `솔`). 가운뎃점과 달리 `+`를 낱말 속 글자로 본 후보는 남기지 않는다. 자르지 않는 것: `++`, `+=`, `C++`, 단위 맨 앞의 `+3`(수 앞의 부호), 코드 구간 안, 주소·경로·옵션 안(`special`이 아는 조각). `+`뿐인 단위는 `+[더하기]`와 `+[연결]`의 경합이다. 쉼표·가운뎃점·더하기의 쓰임은 정하지 않는다.
- **사건번호 꼴은 안을 읽지 않는다.** 단위가 연도(숫자 두 자리나 네 자리), 사건 부호(한글 한~세 음절. 대법원 재판예규 「사건별 부호문자의 부여에 관한 예규」의 부호: `다`, `도`, `회합`, `카기전`), 일련번호(숫자 열. 바로 뒤에 영문이 이어지지 않는다)로 시작하면(`2004다25123`, `97도2836`) 그 안에서 낱말이 시작하거나 끝나지 않는다(`caseNumber`, `caseNumberEnd`. `prepare`가 `fill`로 막는다). 그래서 표에 없는 낱말 하나(이름 없음)로 서고, 뒤의 단위·조사는 그 뒤에 붙는다(`2008회합9+호[단위:호]+로[부사격:로]`). 부호 자리가 큰 수(`17만2000`)이거나 가지번호를 잇는 조사 `의`(`11의2`, `branchJoint`)이면, 또 부호 자리가 수 뒤 조각(단위)이고 일련번호 바로 뒤에 다시 수 뒤 조각이 읽히면(`2020년3월`, `36도5분`) 사건번호가 아니다. 연도 길이와 부호 길이의 한도는 `caseYearLens`, `caseMarkMax`다.

## 여닫는 기호

- 대상은 닫힌 표(`pairRows`, 값은 `pkg/data/pairs.tsv`)의 기호다: `( )`, `{ }`, `[ ]`, `< >`, `" "`, `' '`, 둥근 따옴표 `“ ”` `‘ ’`, 낫표와 화살괄호 `「」『』《》〈〉`. 이름은 기호의 종류와 상관없이 `열기`와 `닫기` 둘이고 뒤에 깊이를 적는다: `([열기:1]`, `[[열기:2]`, `][닫기:2]`, `)[닫기:1]`. 깊이는 기호 종류를 가리지 않고 하나로 센다. 안쪽은 평소대로 읽는다(JSON인지, 코드인지 가리지 않는다).
- 확정하지 않는다. 자르는 단계는 "지금 기호가 열려 있을 수 있는 방식들"을 들고 문장을 앞에서부터 훑는다(`cutter.open`: 방식 하나는 열려 있는 여는 기호의 차례다. 처음에는 아무것도 열리지 않은 방식 하나). 기호를 만나면 방식마다 그 기호의 그래프를 돌려(`cutter.reads`, `cutter.judge`) 선 후보마다 방식을 하나씩 잇는다. 여는 기호는 그 방식에 열린 수보다 하나 깊게 열고, 닫는 기호는 같은 종류의 가장 가까운 여는 기호를 닫는다(깊이는 그 여는 기호의 깊이이고, 그 사이에 열리고 닫히지 않은 것은 함께 걷힌다). 깊이가 여럿 가능하면 후보를 따로 낸다: 한 후보에는 깊이가 하나다(`([열기:1]`과 `([열기:2]` 두 줄). 깊이만 다른 후보의 성립과 선호는 같다. 한도는 없다. 후보의 차례는 방식의 차례다(`ordered`: 처음 나온 차례 그대로, 열기·닫기나 깊이로 다시 놓지 않는다). 첫 방식은 앞의 기호들을 저마다 1위 후보로 읽은 방식이므로, 여닫는 글자가 같은 따옴표는 앞에서 같은 따옴표가 열렸으면 `닫기`가 먼저, 아니면 `열기`가 먼저 선다(`'안채'인`의 둘째 `'`는 `닫기:1`이 1위). 따옴표 안의 괄호는 깊이 2가 먼저다.
- 후보마다 그래프가 있다(`pairGraph`, 이름은 `열기:(`, `닫기:)` 꼴). 주장은 "이 기호는 묶음을 연다/닫는다"이고 예외는 이렇다.

| 후보 | 예외 |
|---|---|
| 닫기 | 같은 종류의 여는 기호가 열려 있지 않다(`MarkIs`, `MarkOpened`에 `Not`) |
| 여닫는 글자가 같은 따옴표(`"`, `'`)의 열기 | 같은 따옴표가 열려 있다(`MarkOpened`). 그래서 열려 있는 방식에서는 닫기로, 아닌 방식에서는 열기로 읽는다 |
| `'`, `’` | 낱말 가운데에 끼어 있다(`MarkBoth`, 양쪽이 영숫자 열: `it's`, `O'Brien`) |
| `<`, `>` | 앞뒤가 모두 빈칸이다(`MarkApart`: `x < y`), 붙임표나 등호와 맞닿아 있다(`MarkArrow`: `->`, `=>`, `<=`) |
| 짝 없는 닫기(`"`, `'`, `”`, `’`: `loneShuts`) | 어느 방식에서든 같은 종류의 여는 기호가 열려 있을 수 있다(`MarkIs`, `MarkOpenedAny`), 앞에 글자가 바로 붙어 있지 않다(`MarkIs`, `MarkAfterWord`에 `Not`), 뒤에 한글이 바로 붙어 있지 않다(`MarkRight`, `SideHangul`), `'`·`’`는 낱말 가운데에 끼어 있다(`MarkBoth`) |

- 어느 방식에서도 후보가 서지 않는 기호는 여닫는 기호가 아니다: 자르지 않고 전처럼 낱말 속 글자(가장자리에 있으면 가장자리 기호)로 둔다. 열려 있는 것이 없는 자리의 `)`가 그렇다.
- **짝 없는 닫는 따옴표.** 닫을 수 있는 따옴표 `"` `'` `”` `’`(코드 상수 `loneShuts`. 괄호류는 넣지 않는다: `1)`, `가)` 같은 목록 번호)는 보통 닫기 그래프 뒤에 닫기 그래프를 하나 더 갖는다(`loneShutGraph`, `addLoneShut`. 이름은 보통 닫기와 같은 `닫기:"` 꼴). 둘은 한 방식에서 함께 서지 않는다: 보통 닫기는 그 방식에 같은 종류가 열려 있어야 서고, 이 그래프는 어느 방식에도 열려 있지 않아야 선다(`candidates`가 방식을 돌기 전에 `c.open` 가운데 하나라도 같은 종류를 품으면 `MarkOpenedAny`를 싣는다). 앞말에 붙고 뒤에 한글이 바로 붙은 자리(`좋다"고`, `있다”며`, `경우”에`)에서 선다. 깊이는 보통 닫기와 같은 셈(같은 종류의 가장 가까운 여는 기호의 깊이)으로 여는 기호가 없어 0이고(`”[닫기:0]`), 아무것도 닫지 않아 다음 방식은 지금 방식 그대로다(`judge`: 열린 것을 걷지 않는다). 여닫는 글자가 같은 `"`·`'`는 열기 후보와 함께 나온다(`"[열기:1]`과 `"[닫기:0]`, 성립·선호가 같다). 뒤에 붙은 조사·맺음은 다른 닫는 기호처럼 그 뒤 경합에 줄기 없이 선다(`+고[맺음:고]`, `+며[맺음:며]`, `+라고[맺음:라고]`). 왼쪽이 마침표인 자리(`다."고`)는 앞이 글자가 아니라 서지 않는다. 띄어 쓰지 않고 앞말에 붙인 여는 따옴표(`그는"좋다"고`의 첫 `"`)와 숫자 바로 뒤의 따옴표(`5'10"이다`의 `"`)에도 `"[닫기:0]`이 함께 선다.
- 헷갈리는 기호(`'`, `<`, `>`: 표의 `unsure`)는 열기·닫기 후보와 함께 글자로 본 후보(이름 없음)를 낸다: `'`는 `'[열기:1]`과 `'`의 경합이다. 그 방식은 열린 것이 그대로인 채로도 남는다. 헷갈리지 않는 기호도 후보가 서지 않는 방식이 섞여 있으면 글자로 본 후보가 함께 나온다.
- 여는 후보만 있는 기호는 홀로 한 단위다. 닫는 후보가 있는 기호는 뒤에 글자가 바로 붙어 있으면 그 글자까지 한 단위다(자르는 단계의 단위는 그대로다). **기호는 언제나 제 경합이다**: `readUnit`은 그런 단위(`readOnto`)를 기호 홀로의 경합(`spread`가 후보마다 갈래를 편 것: `)[닫기:1]`)과 붙은 글자의 경합으로 가른다. 붙은 글자의 경합은 머리 없는 평소 단위로 읽은 후보(통짜 새 낱말, 낱말 + 표지)에, 머리 달린 후보 가운데 기호를 첫 어절의 첫 조각으로 삼은 후보를 옮겨 합친 것이다(`moved`, `movedOne`): 첫 어절에서 머리 조각을 빼면 줄기 없는 어절이 되어(`Attach`) `+를[목적격:를]`로 찍히고, 성립은 그대로(1.00), 선호는 머리 기호 몫(머리만으로 선 어절의 선호)을 뺀 값이다. 모든 어절의 끝 자리에서 머리 길이를 뺀다. 기호를 낱말 속 글자로 삼킨 후보(`)를` 통짜)는 옮기지 않는다. 그 몫은 글자만으로 읽은 후보(`를` 통짜 새 낱말)가 맡는다. 코드 구간(백틱)의 머리는 이대로 한 경합이다(`` `a b`[코드]+를 ``). 뒤에 기호가 이어지면 닫는 기호는 홀로 한 단위다. 경합 사이에 빈칸이 있었는지는 `Contest.Glued`가 알려 준다.
- **숫자 바로 뒤의 따옴표.** `"`와 `'`는 숫자 바로 뒤에도 여닫는 기호이고(`pairs.tsv`의 조건에서 "숫자 뒤 안 됨"을 뺐다) 단위 표(`units.tsv`)의 글자이기도 하다(`"`는 인치·초, `'`는 피트·분). 자르는 단계는 다른 여닫는 기호와 똑같이 자르되, 숫자 바로 뒤에 있고 단위 표의 글자인 기호는 단위에 그 사실을 싣고(`unit.measure`) 열려 있을 수 있는 방식에 이 기호를 만나기 전의 방식 전부를 더한다(단위로 읽으면 아무것도 열리거나 닫히지 않는다. `opened`). 그 기호의 경합에는 열기·닫기 갈래 뒤에 단위 표의 줄마다 갈래가 하나 더해진다(`measured`: `"[단위:인치]`, 줄기 아님, 성립 1, 선호는 단위의 선호). 그래서 `"6"`의 뒤 따옴표는 `"[닫기:1]`, `"[단위:인치]`, `"[단위:초]`의 경합이고, 따옴표 두 쌍이 든 문장에서 둘째 쌍의 열기·닫기도 선다. 영숫자 사이의 `'`(`5'10"`의 `'`)는 낱말 속 글자이고(`MarkBoth`) 낱말 표 없이도 `5[수]+'[단위:피트] 10[수]`가 선다(`units`: 바로 뒤 글자가 숫자이면 낱말 표가 없어도 단위 후보를 기각하지 않는다).

## 가장자리 기호

- 단위의 글자 앞뒤에 붙은 기호와 기호뿐인 단위는 같은 글자가 이어진 열마다 경합 하나로 올린다(`edgesOf`, `signContests`). 이름이 붙는 기호는 닫힌 표(`signNames`)에 있고 후보마다 그래프가 있다(`signGraph`). 선 후보마다 갈래 하나이고 성립 1, 선호 0이다. 후보가 서지 않은 열과 표에 없는 기호는 이름 없이 글자만 올리고, 이웃한 그런 열은 한 경합으로 잇는다(`->`, `^^;`).

| 기호 | 후보 | 예외 |
|---|---|---|
| `,` | `쉼표` | 같은 기호가 이어진다 |
| `?` | `물음표` | 없음(몇 개든: `??[물음표]`) |
| `!` | `느낌표` | 없음 |
| `:` `;` | `쌍점`, `쌍반점` | 같은 기호가 이어진다, 어절 끝에 있지도 단위 전체이지도 않다 |
| `~` `∼` `～` `〜` | `물결표` | 어절 끝에 있지도 단위 전체이지도 않다. 이 예외는 양쪽이 한글일 때 꺾인다(예외 "양쪽이 한글이다", `MarkBoth`: 글자 사이 `여름~가을`) |
| `/` | `빗금` | 양쪽이 한글이 아니다(`MarkBoth`에 `Not`). 이 예외는 단위의 가장자리(읽는 글자 뒤, 읽는 글자 바로 앞, 홀로)에서 꺾인다(예외 "단위의 가장자리에 있다", `MarkIs`: `수/ 없다`, `files/,`, 홀로 선 `/`가 `/[빗금]`). 글자 사이에서는 양쪽이 한글일 때만 선다 |
| `…` | `줄임표` | 없음(몇 개든: `……[줄임표]`) |
| `―` `—` | `줄표` | 없음(몇 개든) |
| `#` | `제목` | 입력 줄의 맨 처음이 아니다, 바로 뒤가 빈칸이 아니다. 이름에 `#`의 개수를 붙여 찍는다(`##[제목2]`). 개수에 한도는 없다 |
| `#` `@` | `샵`, `골뱅이` | 같은 기호가 이어진다, 뒤에 글자가 바로 붙지도 단위 전체이지도 않다 |
| `#` `@` | `태그`, `명칭` | 같은 기호가 이어진다, 뒤에 글자가 바로 붙지 않았다 |
| `·` `ㆍ` `・` `‧` `․` `•` | `가운뎃점` | 같은 기호가 이어진다 |
| `+` | `더하기`, `연결` | 같은 기호가 이어진다, 다른 기호와 맞닿아 있다(`MarkBySign`) |
| `.` | `마침표`, `줄임표` | 위의 점 그래프 |

- `#`과 `@`는 후보를 둘 낸다: 기호 그 자체(`#[샵]`, `@[골뱅이]`)와 구실로 본 후보(`#[태그]`: 뒤의 말이 주제 표시다, `@[명칭]`: 가리키는 대상의 이름이다). 줄 맨 처음의 `# `는 `#[제목1]`과 `#[샵]`이다. 구실로 본 후보만 서면(`roleNames`: 줄 맨 처음의 `## `) 글자만 낸 후보를 곁에 둔다(`##[제목2]`와 `##`). 낱말 뒤에 붙은 `#`(`C#`)는 이름 없이 글자만 올린다. 쉼표의 쓰임(열거, 절 사이, 부름)은 정하지 않는다.
- 사실은 `rule.Mark`에 싣는다(`edgeFacts`): 열의 길이, 양옆의 글자, 단위 전체인가, 읽는 글자 뒤에 있는가, 읽는 글자가 바로 뒤에서 시작하는가, 입력 줄의 맨 처음인가, 바로 뒤가 빈칸인가, 다른 문장부호·기호가 바로 옆에 있는가(`MarkBySign`).

## 낱말 표

`Options.Words`(명령에서는 `--words` 또는 환경 변수 `NLGEUL_WORDS`)로 낱말 표를 주면 줄기를 그 표에서 찾는다. 표가 없으면 위에 적은 대로만 읽는다. 표의 형식은 탭으로 나눈 칸 다섯(검색 키, 갈래, 불규칙 유형, 횟수, 바른 꼴)이고 칸 넷뿐인 줄도 읽으며 `#`으로 시작하는 줄은 건너뛴다. 불규칙 유형은 ㄷ, ㅅ, ㅂ, ㅎ, 르, 러, 우를 읽는다. 낱말은 표의 줄이고 그래프가 아니다. 줄기를 표(`map`)에서 찾아 그 갈래·횟수·길이를 갈래별 그래프 여섯 개(`열쇠:체언`, `열쇠:동사`, `열쇠:형용사`, `열쇠:부사`, `열쇠:관형사`, `열쇠:홀로`)에 넘긴다(`stemVerdict`, 같은 사실은 한 번만 평가해 둔다. 기억의 열쇠는 그래프에 준 사실 전부다). 세 겹으로 쓴다(`--layers`로 겹을 줄여 잴 수 있다).

1. 여부: 표에 있는 줄기(풀어 쓴 꼴)는 아는 낱말이다. 없는 토큰 열은 그대로 새 낱말이다. 선호는 log10(횟수 ÷ 표의 총 횟수)다. 갈래가 둘인 키는 뒤를 받는 갈래의 횟수를 쓴다(`taken`: 명사 `작`은 형용사 `작`만큼 흔하지 않다).
2. 갈래 맞춤과 증거의 세기: 갈래별 그래프가 줄기를 판정한다. 주장 "이 줄기는 아는 낱말이다"를 예외 `rule.StemTail`(갈래가 뒤에 붙은 것을 받지 않는다)이 꺾고, 동사·형용사 그래프에서는 예외 `rule.PieceIs`(바로 앞 낱말이 꾸밈 맺음으로 끝난다, 바로 앞 낱말이 관형사다)도 꺾고, 홀로 그래프에서도 그 두 예외가 꺾고, 반박 `rule.SeenFew`(관측이 적다. 횟수 0인 줄도 한 번과 같이 친다)와 `rule.ShortKey`(한 음절이다)가 낮춘다. 닫힌 표의 구어 꼴(`spoken`: `것`을 구어로 이르는 `거`)에서는 예외 `rule.Listed`가 반박 "관측이 적다"를 꺾는다: 글말에서 센 횟수가 적다는 것은 구어 꼴에 불리한 증거가 아니다(`거[의존명사:거]`의 성립이 한 음절 반박만 받은 값이 된다. 선호는 그대로다). 줄기의 낱말이 단위 전체이면(줄기가 단위의 첫머리에서 시작하고 그 뒤가 그 줄기의 표지뿐이다) 예외 `rule.PieceIs`(기준 `PieceSole`)가 반박 "한 음절이다"를 꺾는다: 그 반박의 까닭은 한 음절 낱말이 긴 글자열 속에서 우연히 겹치기 쉽다는 것인데, 띄어쓰기가 낱말의 양 끝을 정해 준 자리에는 그 까닭이 없다(`하+자`, `가+는`의 줄기 성립이 1이 된다. 단위 안에 낱말이 둘 이상이면 전과 같다). 본용언의 어/아 꼴 바로 뒤에 붙여 쓴 보조 용언의 줄기에 서술어 꼬리가 붙으면(`auxAfterConn`, 위 "색인과 그래프"의 보조 용언 문단) 예외 `rule.PieceIs`(기준 `PieceConn`)도 반박 "한 음절이다"를 꺾는다: 「한글 맞춤법」 제47항이 붙여 씀을 허용한 그 자리에서는 줄기의 앞 끝을 본용언의 어/아 맺음이, 뒤 끝을 서술어 꼬리가 정해 준다(`하+(여) 주+(어)`의 `주[보조 용언:주]` 마디 성립이 관측이 넉넉하면 1이 된다. 읽기를 지우지 않고 차례만 바꾼다). 성립은 그래프가 낸 값 그대로다: 두 반박이 다 걸려도 새 낱말보다 조금 위다. 체언(명사, 대명사, 수사, 식별자)은 홀로 서거나 조사를 받고, 동사 줄기는 선어말과 모든 맺음을, 형용사 줄기는 동사 전용 맺음(`verbClosings`: 현재 ㄴ다/는다, 청유, 목적·의도)을 뺀 맺음을 받고(서술격 이다는 연결 어미 자를 받는다: `학자+이+자`. 표가 연결 자와 청유 자를 한 이름으로 두어 서술격 뒤에서는 둘을 가르지 못한다), 느냐와 그 인용 꼴(`existClosings`, 표의 집합 `동사·있다·없다·계시다`)은 동사 줄기와, 형용사 가운데 있다·없다·계시다의 줄기(`existStems`, 집합 `있다·없다·계시다`)와, 선어말 시·었·겠 뒤의 어느 줄기든 받는다(`없+느냐`, `좋+았+느냐`. 사전의 -느냐. `좋+느냐`는 서지 않는다. 형용사 그래프의 예외 `StemTail`을 줄기 목록 `Listed`가 꺾고, 뒤가 그 맺음이 아니면 다시 `StemTail`이 그것을 꺾는다: `existExcept`. 선어말 뒤는 꼬리의 갈래를 정할 때 본다: `tailClass`) 둘 다 홀로 서지 못하고, 부사는 홀로 서거나 보조사를 받고, 관형사와 그 밖은 홀로 선다. 닫힌 집합 낱말도 같은 판정을 받는다. 닫힌 집합 낱말의 이름(`관형사:이`)은 그 집합의 갈래로 섰을 때만 찍는다(`ownName`): 조사 앞의 `이`는 낱말 표의 체언으로 선 것이라 `이[열쇠:체언]+가`로 찍고, 두 집합에 든 `두`는 선 쪽의 이름만 찍는다(`두[보조 용언:두]+고`). 홀로 설 수 있는 아는 낱말은 단위 안에서도 표지 없이 어절이 된다.
3. 구조 값: 단위 안의 경계, 글자에 흔적이 없는 조각, 줄기에 값을 매긴다(`costBoundary`, `costUnseen`, `costPiece`). 색인의 표지(조사, 선어말, 맺음, 단위, 기호)는 조각 값을 치르지 않는다. 구조 값은 낱말 표가 없을 때도 매긴다.

불규칙 용언(`irr_table.go`, `changed`, `variants`). 낱말 표의 용언 줄기가 꼬리 앞에서 바뀐 꼴은 그 꼬리와 묶어서만 읽고, 본디 줄기로 찍는다. 바뀐 꼴은 홀로 줄기가 되지 않는다. 바뀐 꼴이 다른 낱말과 같으면 둘이 나란히 선다. 낱말 표의 `…하` 용언 줄기(두 음절 이상)는 「한글 맞춤법」 제40항에 따라 `치`·`케`·`타`·`토록`·`코자`·`컨대` 앞에서 `하`가 줄어든 꼴로도 읽는다(`원하+치[맺음:지]`, `가능하+케[맺음:게]`, `단언하+컨대[맺음:건대]`. 짝은 닫힌 표 `haPairs`, 꼬리는 `haTails`). 조각은 적힌 글자에 본디 맺음 이름을 단다. 뒤에 조사가 붙으면 서지 않고(맺음 그래프의 예외 `PieceRight`: `정치는`, `위치를`은 `정하+치`, `위하+치`로 읽지 않는다), 적힌 꼴은 제 횟수 없이 음절 값으로 선호를 친다(`addHa`). 같은 항 붙임 2에 따라 `하` 앞 음절의 받침이 [ㄱ, ㄷ, ㅂ]으로 소리 나면(「표준 발음법」 제9~11항: ㄱ ㄲ ㄳ ㄺ ㅋ, ㄷ ㅅ ㅆ ㅈ ㅊ ㅌ, ㅂ ㅄ ㄿ ㅍ, 닫힌 목록 `voicelessEnds`) `하`가 아주 준 꼴로도 읽는다: 안울림 받침 뒤의 `생각건대`는 `생각하+건대[맺음:건대]`다. 이렇게 읽는 맺음은 `건대` 하나다(`haWhole`. `넉넉지`의 `지`는 읽지 않는다).

|---|---|---|---|
| ㄹ 탈락 | 살 → 사 | ㄴ·ㅅ으로 시작하는 꼬리, 합쳐진 ㄴ·ㄹ·ㅂ 앞. 유형 표시와 무관하게 ㄹ 받침 줄기 전부 | `살+(ㄴ)다`, `알+는` |
| ㄷ | 듣 → 들 | 어/아, 으가 든 꼴 앞 | `듣+었+다`, `듣+으+니` |
| ㅅ | 짓 → 지 | 어/아, 으가 든 꼴 앞 | `짓+어`, `짓+은` |
| ㅂ | 돕 → 도우 (돕·곱은 도오도) | 으를 받는 꼬리의 모음 뒤 꼴, 합쳐진 어/아 앞 | `덥+(어)서`, `돕+(아)` |
| ㅎ | 파랗 → 파라, 파래 | 으를 받는 꼬리와 네 앞 / 합쳐진 어 | `파랗+(ㄴ)`, `그렇+(어)` |

오표기 줄(다섯째 칸이 있는 줄, 예 `맞기\t동사\t규칙\t0\t맡기`). 키는 틀린 표기이고 바른 꼴은 표의 다른 줄이다. 이 줄은 낱말(`lex`)에도 횟수의 합에도 들지 않고 적힌 꼴로 따로 둔다(`typos`): 들이면 `맞기`를 새 낱말로 읽는 후보가 아는 낱말 후보로 바뀌어 사라진다. 오표기 후보는 더해지기만 한다. 꼬리 앞의 글자(합쳐진 조각은 되돌린 끝 음절)가 적힌 꼴이고, 꼬리를 하나 더 낸다(`typoCandidates`, 차례는 본디 → 불규칙 → 오표기): 줄기는 바른 꼴(`맡기`)로 찾고 갈래 맞춤·되돌림·선호가 바른 꼴로 돈다. 바른 꼴이 오표기 줄의 갈래로 그 꼬리 앞에 서야 읽는다(`misspelt`: 갈래별 그래프가 줄기를 판정하되 `PieceMisspelt` 사실을 건다). 갈래 그래프 여섯 개 모두에서 반박 `rule.PieceIs`(기준 `PieceMisspelt`)가 주장을 `forceTypo`(0.28)로 낮추고 이를 꺾는 예외는 없다. 바르게 쓴 낱말보다 낮게 선다(그 반박만 걸리면 성립 2/(1+0.28)-1, 약 0.56. 바른 낱말의 성립이 0.98인 자리의 `맡기`는 0.55로 찍힌다). 찍을 때 줄기 이름 끝에 `,오타정정:<적힌 꼴>`이 덧붙는다(`corrected`, 기호와 이름은 `consts.go`의 상수 둘): `맡기[열쇠:동사,오타정정:맞기]+(어)[맺음:어(합침)]`. 읽는 자리: 표지 앞의 줄기, 표지 없이 선 낱말(`wholeTypos`: 단위의 끝이 아니어도 아는 낱말처럼 선다. 홀로 선 명사 `역활`, 붙여 쓴 `역활분담`, 하다 앞의 `설겆이하고`), 빗금·붙임표로 묶인 마디(`입력/역활을`: 묶인 마디 가운데 아는 낱말도 영숫자 열도 아닌 것이 오표기 줄에 있으면 바른 꼴로 읽고 첫 바른 꼴만 읽는다. 줄기는 마디를 바른 꼴로 바꿔 기호로 이은 `입력/역할`, 적힌 꼴은 `입력/역활`. 글자 그대로의 후보 옆에 더하는 후보이고 `boundTails`가 꼬리에 `boundTypo`를 달아 낸다). 읽지 않는 자리: 불규칙 줄기의 바뀐 꼴. 동사 줄기는 홀로 서지도 조사를 받지도 않으므로 `맞기`, `맞기가`에는 이 후보가 없다. 표지 없이 선 낱말도 바른 꼴이 표지 없이 설 수 있는 갈래(체언, 부사, 관형사, 홀로)일 때만 선다. 글자 그대로의 낱말 후보는 그대로 남는다. 본디 후보(새 낱말, `맞[열쇠:동사]+기[이름:기]` 들)는 그대로 선다.

닫힌 표의 틀린 표기 낱말(`typoKeys`)은 닫힌 집합 낱말 `거`를 된소리로 적은 `꺼` 하나뿐이고, 닫힌 표이므로 이 줄이 전부다(다른 목록·사전에서 옮긴 것이 아니다). 낱말 표가 있을 때 색인을 지으며 오표기 줄과 같이 든다(`addTypoKeys`: 갈래는 그 낱말이 닫힌 집합으로서 갖는 의존명사이고, 낱말 표에 같은 줄이 있어도 같은 바른 꼴이라 하나로 합쳐진다). 바른 꼴이 닫힌 집합 낱말이면 `misspelt`가 판정할 갈래를 낱말 표의 갈래와 닫힌 집합의 갈래에서 고르고(낱말 표에 `거` 줄이 없어도 선다), 이름은 `known`처럼 닫힌 집합의 이름을 준다(`ownName`): `거[의존명사:거,오타정정:꺼]`. 반박은 다른 오표기와 같다. 받침이나 맺음이 줄기에 합쳐진 `껀데`·`껍니다`도 되돌린 줄기 `꺼`로 읽는다. 꾸밈 맺음 바로 뒤의 `껀`(거+는)과 `껄`(거+를)은 `건`·`걸`과 같은 길로 읽는다(`typoContracts`, 낱말 표가 있을 때만. 줄기가 틀린 표기 `꺼`로 적혔음을 `contract`의 칸 `wrote`에 싣고, `fixed`가 그 꼬리에 `wrote`와 닫힌 집합의 갈래를 달아 `stemOf`가 `misspelt`로 판정한다: `거[의존명사:거,오타정정:꺼]+(를)[목적격:를]`. 띄어 쓴 꼴도 `attached`가 읽는다. `께`(거+이)는 읽지 않는다).

ㄷ·ㅅ 뒤의 으가 든 꼴은 본디 줄기의 끝 음절로 판정한다(`irrTails`, `linked`: `지은`의 은은 `짓` 뒤라 선다). 표가 규칙이라 적은 그러·이러·저러·어쩌의 그래 꼴은 닫힌 표(`eoStems`)로 읽는다. 받침 하나뿐인 맺음(ㄴ, ㄹ, ㅁ)은 낱말 표가 있으면 앞말이 표의 용언 줄기일 때 어느 음절 밑에서든 읽고(`예쁘+(ㄴ)`), ㄹ 받침 줄기의 ㅁ은 ㄻ에서 뗀다(`살+(ㅁ)`). 체언 + 이 빠짐으로는 열지 않는다.

맺음 오표기. 닫힌 표(`typoClosings`, `pkg/data/typo-closings.tsv`의 17줄)에 든 틀린 표기의 맺음은 바른 맺음으로 찍고 이름 끝에 적힌 꼴을 덧붙인다. 표는 떠올려 적은 흔한 오표기이고 다른 목록·사전에서 옮긴 것이 아니다. 받침 ㄹ 밑에 쓴 꼴: `께`(ㄹ게), `껄`(ㄹ걸), `찌`(ㄹ지), `쑤록`(ㄹ수록), `려고`·`려면`(받침 ㄹ이 든 `갈려고`, `할려면`. 줄기는 `가`, `하`). 통음절 꼴: `을께`(을게), `을껄`(을걸), `을찌`(을지), `을쑤록`(을수록), `을려고`(으려고), `을려면`(으려면), `읍니다`(습니다), `슴`(이름 음), `구만`(구먼), `예요`(에요), `에요`(예요). 바른 맺음의 항목을 이름으로 찾아 복사해 만든 항목이 색인에 들고(`addTypoClosings`, `typoClosingEntry`), 이름·갈래·횟수·앞말 조건·`head`는 바른 맺음의 것 그대로라 이름으로 묻는 목록과 예외가 바른 맺음과 똑같이 걸린다. 다른 것은 꼴·받침(적힌 꼴의 것), 붙는 앞말(받침 밑 꼴은 어디든, 통음절 꼴은 바른 맺음의 것), 새 칸 `wrote`(적힌 꼴, `ㄹ께`)와 `right`(찍는 꼴, `(ㄹ)게`)다. 그래프는 적힌 꼴로 찍고(`markerGraph`) 반박 `rule.PieceIs`(기준 `PieceMisspelt`)가 `forceTypo`로 낮춘다(바른 꼴의 성립이 1인 자리에서 2/(1+0.28)-1, 약 0.56). 횟수의 합과 닫힌 맺음의 집합에는 들지 않는다. 오표기 항목은 같은 글자의 바른 항목과 한 조각으로 합쳐지지 않고(`entryGroup`), 그 글자가 새 낱말로 읽히는 후보(`구만`, `슴`)는 그대로 선다(`markedFrom`). 바른 맺음이 설 수 없는 앞말에는 서지 않는다(`책께`는 받침 ㄹ이 없다). 모르는 줄기 뒤에서 바른 꼴과 같은 방식으로 서는 것은 같다(`예쁠려고`의 `예쁘+려고`는 `예쁘려고`와 같이 이름 없는 줄기). 표에 없는 틀린 맺음은 읽지 않는다. 찍을 때 표지 이름 끝에 덧붙는 것도 `corrected`다(`게[맺음:ㄹ게,오타정정:ㄹ께]`).

사이시옷으로 묶인 줄기(`saisiotCandidates`, 「한글 맞춤법」 제30항). 표에 없는 줄기(아는 낱말도, 원자도, 빗금·붙임표로 묶인 줄기도 아닌 것)가 낱말 표의 체언 둘을 사이시옷이 한 줄기로 묶은 꼴이면 갈래 체언의 후보 `사이시옷:ㅅ`을 더한다(`전셋값[사이시옷:ㅅ]+이[주격:이]`). 이름은 묶인 줄기(`대비:/`, `붙임:-`)처럼 갈래와 묶는 글자다. 표의 낱말은 고치지 않는다. 자리는 줄기의 앞에서부터 다음을 모두 채우는 첫 자리다(`saisiotParts`). (1) 줄기의 둘째 음절부터 끝 음절 앞까지에서 받침이 ㅅ 하나인 음절이다. 앞말은 두 음절 이상이다: 제30항에는 한 음절 앞말(`귓밥`, `콧물`)도 있으나, 첫 음절의 ㅅ 받침은 접두사(`헛기침`), 관형사 `첫`, ㅅ으로 끝나는 낱말, 옛 표기의 ㅆ과 글자로 가를 수 없어 측정으로 뺐다(조항 근거는 아니다). (2) 그 음절에서 ㅅ을 뗀 데까지(모음으로 끝난다)가 앞말이고 낱말 표의 체언이다. (3) ㅅ 받침 그대로 그 음절까지는 낱말 표나 닫힌 집합의 낱말이 아니다: 그러면 그 ㅅ은 그 낱말 자신의 받침이다(`오얏 나무`, `이것 밖+엔`). (4) 다음 음절의 첫소리가 ㄱ·ㄷ·ㅂ·ㅅ·ㅈ(된소리로 난다), ㄴ·ㅁ(ㄴ 소리가 덧난다), 또는 ㅇ이고 모음이 ㅣ·ㅑ·ㅕ·ㅛ·ㅠ다(ㄴㄴ 소리가 덧난다, 「표준 발음법」 제29항: `배춧잎`). 그 음절이 `이` 자체이면 아니다(제27항 [붙임 3]: 그 자리의 이는 `니`로 적는다)(`saisiotOnset`, 첫소리 번호는 `rule.ChoOf`). ㅊ·ㅋ·ㅌ·ㅍ·된소리·ㅎ·ㄹ 첫소리(`아랫층`, `짜릿함`)에서는 서지 않는다. (5) 그 뒤부터 줄기 끝까지가 뒷말이고 낱말 표의 체언이다. 성립은 앞말(홀로 선다)과 뒷말(그 줄기의 꼬리를 받는다)의 체언 성립 가운데 작은 것이고(`nominalVerdict`), 두 마디 모두 반박 "한 음절이다"를 걷고 판정한다(`knownCandidates`의 `sole`): 앞말의 끝과 뒷말의 앞은 제30항의 ㅅ 받침이, 뒷말의 끝은 꼬리가 정해 주므로 긴 글자열 속에서 우연히 겹친 낱말이 아니다. 걷지 않으면 조사를 먹은 긴 뒷말(`전깃불이` = `전기` + `불이`)이 앞선다. 선호는 앞말과 뒷말의 체언 선호(체언으로서의 횟수)의 합이다(`stemPref`가 표에 횟수가 없는 아는 줄기를 이렇게 가를 때. 횟수가 없는 마디는 묶인 줄기의 마디처럼 글자마다 토큰 하나로 친다). 같은 줄기의 새 낱말 후보도 함께 남는다(새 낱말의 길이 제한 `farNew`에 걸리면 사이시옷 후보만 남는다). 낱말 표의 낱말·묶인 줄기와 달리 사이시옷 읽기는 낱말의 어원(고유어·한자어·외래어)을 보지 못한 짐작이라, 외래어나 이름에서 틀릴 때 새 낱말 읽기가 사라지지 않게 한다. 어원을 보지 못하므로 규범에 어긋난 한자어끼리의 표기(`소숫점`)와 외래어 앞말도 이 후보로 읽힌다. 표에 이미 있는 합성어(`나뭇가지`, `숫자`)는 아는 낱말이 먼저라 이 길을 타지 않는다.

반박의 힘, 문턱, 구조 값(`forceNew`, `seenEnough`, `forceFew`, `forceShort`, `forceWhole`, `forceClash`, `forceTypo`, `forceDropAdn`, `cost…`)은 자리 채움 값이다. 몇 가지 값을 문장 묶음에 재어 고른 것도 있으나 조각의 정답이 있는 자료로 맞춘 값은 아니다. 낱말 표가 있으면 후보의 차례는 선호 + log10(성립)이다(`before`). 성립이 낮은 후보도 남고 뒤로 갈 뿐이다.

그래프는 낱말 표 없이 521개(간선 1056), 낱말 표가 있으면 572개(간선 1201)다.

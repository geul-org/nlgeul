# nlgeul

한국어 문장을 문법 표만으로 분석하는 실험 도구다. Go 모듈 `github.com/geul-org/nlgeul`과 cobra CLI `nlgeul`이고, 하위 명령은 `parse`와 실험용 `token`, `hypo`다(cobra의 `help`는 남고 `completion`은 껐다). 2026-11-10 이전의 분석기(명사 분리·식별)는 git 기록에 남아 있다.

## nlgeul parse

```sh
go install ./cmd/nlgeul
nlgeul parse "이것은 문장을 분해한다"
```

문장 하나(인자 하나)를 띄어쓰기로 나눠 어절마다 `어절:문장성분`을 한 줄씩 찍는다. 이름은 `주어`, `목적어`, `보어`, `서술어`, `관형어`, `부사어`, `독립어`, `미정`이고, 풀이가 여럿이면 `|`로 잇는다. 단어와 조사, 용언의 줄기와 꼬리 조각(선어말 칸, 맺음, 요, 인용의 고, 명사 뒤 하다·되다·시키다) 사이에는 `+`를 넣는다. 줄기와 조각이 한 음절에 합쳐진 곳은 표면 꼴 그대로 둔다(`지시+해서`, `합+니다`).

```
이것+은:관형어|주어|목적어
문장+을:목적어|관형어
분해+한+다:서술어
```

사전과 낱말 목록 없이 조사, 어미 사슬, 문법 형태소의 표만으로 어디까지 되는지 재는 실험이다. 낱말로는 표에 적힌 닫힌 집합만 안다: 의존명사(거, 것, 수, 줄, 데, 때, 대로, 뿐, 만큼), "것"의 줄임(게, 건, 걸), 보조 용언(주다, 보다, 버리다, 놓다, 두다, 있다, 지다), 지시·수 관형사(이, 그, 저, 이런, 어떤, 무슨, 한, 두), 접속 부사(그리고, 그러나, 그래서, 하지만). 코드 주석의 `particles.md`, `endings.md`, `morphemes.md`는 그 표를 적은 작업 문서의 이름이고 이 저장소에는 없다. 표는 코드 안에 옮겨 두었고 실행 때 md를 읽지 않는다.

입력 문장의 전제조건(어긴 입력을 고쳐 읽지 않는다):

1. 동사 서술은 반드시 마지막에 온다.
2. 띄어쓰기를 올바로 한다.
3. 조사를 반드시 올바로 붙인다.

## nlgeul token (실험)

```sh
nlgeul token "다음으로써"
nlgeul token --trace "다음으로써"
```

토큰(음절) 스트림을 표지 풀이마다 하나씩 둔 판정 그래프로 읽어 어절로 끊어 올린다. 띄어쓰기와 문장 부호는 확정 경계이고, 그 사이 단위에서 읽기들이 합의한 자리에서 끊는다. 읽기가 갈리면 경합으로 갈래마다 성립과 선호를 찍는다. 줄기에 합쳐진 조각은 줄기를 본디 꼴로 되돌려 `마시+(ㄴ)다`, `쓰+(어)`처럼 찍는다. 체언 뒤의 서술격 이다는 줄기 `이`를 따로 읽고(`그림+이[서술격:이]+다`, `학생+이+(ㅂ)니다`), 모음 뒤에서 빠진 이는 괄호에 적는다(`학교+(이)+다`). 두 조각이 합쳐진 글자는 풀어 읽는다(`가+시+(었)+다`, `읽+으+시+(었)+다`, `그렇+지+(요)`, `하+(였)+지+(않)+아`, `가+(아)야+(하)+겠+다`, `이것+(이)`, `내+게[부사격:에게]`, `어디+다[부사격:에다]`). 줄기 끝 `되` 뒤에서 어를 빼고 적은 꼴도 읽는다(`되+(어)도`, `되+(었)+다`). 낱말 속에도 흔한 합쳐진 글자(높임 `시`가 든 신·실·심·세, 인용이 줄어든 대·래·재·단·란·잔, 줄어든 선·론·진·긴·길)는 낱말 표가 있고 앞말이 표의 줄기일 때만 다른 풀이와 나란히 읽는다. 영문·숫자 열은 조각 하나이고, 점은 풀이(파일명, 도메인, 소수점, 버전, 마침표, 줄임표)마다 그래프가 판정한다(`task.py[파일명|도메인]+에`). 숫자 열은 수이고 숫자 사이의 기호는 풀이마다 판정한다(`1,000[수]`, `10:30[시각|비율]`, `2026-11-10[날짜]`, `010-1234-5678[전화]`, `192.168.0.1[버전|IP]`, `-3[부호|수]`). 수 바로 뒤의 단위 표 낱말은 단위다(`3[수]+개[단위:개]+를`). 단위 앞의 수는 숫자 열, 붙여 쓴 한글 수사, 표의 영문 글자이고 숫자 뒤에는 큰 수가 이어진다(`한[수]+개`, `7[수]+만[큰 수:만]+장`, `N[수]+개`). 주소, 전자우편, 경로, 명령의 옵션은 조각 하나다(`~/a/b[경로]+를`, `--xx[옵션]`). 이음 `으`와 연결 어미 뒤의 보조사는 조각으로 읽는다(`읽+으+시+고`, `보+지+도`). 문장성분은 정하지 않는다([internal/token/](internal/token/README.md)).

낱말 표가 있으면 더 읽는다: 불규칙 용언의 바뀐 줄기를 본디 줄기로 되돌리고(`듣+었+다`, `돕+(아)`, `모르+(아)`, `그렇+(어)`, `살+(ㄴ)다`), 받침 하나뿐인 맺음을 용언 줄기 밑에서 읽고(`예쁘+(ㄴ)`), 본용언에 붙여 쓴 보조 용언을 읽는다(`지우+(어)+지+(ㄴ)다`). 영숫자 열이나 수 뒤의 `야`를 이가 빠진 서술격으로 읽고(`abc+(이)+야`), 이가 빠진 이름 꼴에 조사가 붙은 것을 읽는다(`문제+(이)+기+도`). 맞춤법에 어긋나게 ㄹ 받침 줄기에 꾸밈 맺음 `은`·`을`을 그대로 붙인 꼴도 표의 용언 줄기 뒤에서 읽는다(`줄+은[꾸밈:은]`).

낱말 표가 있으면 `--words <파일>`이나 환경 변수 `NLGEUL_WORDS`로 준다(탭으로 나눈 칸 넷: 검색 키, 갈래, 불규칙 유형, 횟수). 없으면 문법 표의 닫힌 집합 낱말만 안다. 낱말 표는 이 저장소에 들어 있지 않다. `--stdin`은 표준 입력의 줄마다 문장 하나로 읽는다.

## nlgeul hypo (실험)

```sh
nlgeul hypo "작은 곰이 물을 마신다."
```

문장 하나를 `nlgeul token`과 같이 읽고, 묶음(`nlgeul token`이 한 줄이나 경합 하나로 찍는 구간)마다 읽기를 하나씩 골라 이은 조합(가설)을 모두 나열한다. 첫 줄은 `가설 <수>`이고, 그 뒤 가설마다 한 줄에 순위, 가설의 성립과 선호, 묶음별 읽기(` | `로 가른다)를 찍는다. 정렬은 고른 읽기마다 (선호 + λ·log10 성립)을 내어 모두 더한 값이 큰 순이다(λ = 15). 줄에 찍는 가설의 성립은 고른 읽기들의 성립 가운데 최솟값, 선호는 고른 읽기들의 선호의 합이다. 옵션이 없으면 가설을 모두 찍는다. `--page <N>`이면 N번째 페이지의 가설만 찍는다(페이지는 1부터 센다). 한 페이지의 가설 수는 100이고 `--per-page <K>`로 바꾼다(`--page`와 함께 준다). 이때도 첫 줄은 전체 가설 수이고 순위는 전체 순위 그대로다. 마지막 페이지를 넘는 페이지는 첫 줄만 찍는다. 가설이 1000000개를 넘는 문장은 가설 수만 찍고 오류로 끝난다. 낱말 표는 `--words`나 `NLGEUL_WORDS`로 준다([internal/hypo/](internal/hypo/README.md)).

## 구성

- 어절의 오른쪽 끝을 음절·자모로 읽는 부분은 일반 Go 코드, 읽은 사실로 문장성분을 가리는 판정은 toulmin 그래프다([internal/parse/](internal/parse/README.md)).
- toulmin은 park-jun-woo/toulmin `geul` 브랜치의 Go 모듈(MIT)을 공개 커밋 버전으로 require한다.
- 제3자 구성요소: `github.com/park-jun-woo/toulmin/go`(MIT), `github.com/spf13/cobra` v1.10.2(Apache-2.0), `github.com/spf13/pflag` v1.0.9(BSD-3-Clause), `github.com/inconshreveable/mousetrap` v1.1.0(Apache-2.0). 우리 코드는 CC0다(LICENSE, NOTICE).
- 규칙: filefunc(`codebook.yaml`, 함수·타입별 파일), TSMA, `go test`·`go vet`·`go build`. `go.work`는 쓰지 않는다(`GOWORK=off`).
- 패키지는 [internal/](internal/README.md)과 [pkg/](pkg/README.md), 진입점은 [cmd/](cmd/README.md). 여러 그래프가 함께 쓰는 규칙 함수는 `pkg/rule`에 있다.

# combo

후보의 조합 나열(실험). 이를 부르는 명령은 없고 내부 함수로만 남아 있다. 토큰 층이 올린 구조(`token.Reader.Contests`)를 받아, 경합마다 후보를 하나씩 골라 이은 조합을 세고 정렬한다. 글줄을 다시 읽지 않는다.

| 이름 | 하는 일 |
|---|---|
| `Count` | 후보의 조합 수(경합마다의 후보 수의 곱). 크기에 한도가 없는 수로 낸다 |
| `Picked` | 번호가 가리키는 조합의 후보들. 번호 0은 모든 경합의 첫 후보다 |
| `List` | 모든 조합에 점수를 매겨 정렬한다 |
| `Lambda` | 정렬 공식에서 성립의 무게 λ(15). 상수 하나다 |
| `Line` | 조합 한 줄: 순위, 성립과 선호, 경합별 후보(` | `로 가른다). 후보는 `token.Branch.String`이 찍는다 |
| `Limit` | 나열하는 조합 수의 상한(1000000). 메모리를 지키려는 안전장치이고 상수 하나다 |
| `Page` | 정렬한 조합에서 한 페이지를 잘라 낸다(페이지는 1부터 센다). 그 앞에 있는 조합 수도 함께 내어 순위가 전체 순위로 남는다. 페이지 0은 전부이고, 마지막 페이지를 넘으면 비어 있다 |
| `PerPage` | 한 페이지의 조합 수의 기본값(100). 상수 하나다 |

## 정렬 공식

정렬 기준은 `order.go`의 함수 `order` 하나에 모여 있다. 그 함수만 고치면 정렬이 바뀐다.

- `score`: 고른 후보들에서 조합의 점수(`Score`)를 낸다. 자리(`Place`)는 후보마다 (선호 + λ·log10 성립)을 내어 경합 차례대로 더한 값이다. 성립(`Verdict`)은 후보들의 성립 가운데 최솟값, 선호(`Pref`)는 후보들의 선호의 합이고, 이 둘은 줄에 찍기만 한다.
- `before`: 두 점수 가운데 어느 것이 먼저인가. 자리가 큰 것이 먼저다.

λ는 `lambda.go`의 상수 `Lambda` 하나다(15). 성립이 선호에 견주어 얼마나 무거운가를 정한다: 0이면 선호의 합만으로 정렬하고, 클수록 성립이 낮은 후보를 고른 조합이 뒤로 간다. 값을 바꾸려면 이 상수를 고친다.

성립이 0 이하인 후보는 log10이 없으므로 −∞로 친다. 그런 후보를 고른 조합은 자리가 −∞가 되어 모든 다른 조합 뒤에 온다.

자리가 같은 조합은 번호 순서(앞 경합부터, 토큰 층이 낸 후보 순서)로 남는다(`List`의 안정 정렬). 자리가 −∞인 조합끼리도 그렇다. 후보가 하나뿐인 경합도 다른 경합처럼 토큰 층이 그 후보에 준 성립과 선호로 들어간다(모든 조합에 같은 값을 더하므로 순서는 바꾸지 않는다). 단위 앞뒤의 기호(문장부호, 이름 없는 기호)는 성립 1, 선호 0이라 조합의 점수를 바꾸지 않는다. 한 기호의 후보가 여럿인 경합(깊이만 다른 `열기`·`닫기`, 글자로 본 후보, `샵`과 `태그`)은 후보들의 성립과 선호가 같아 조합의 수만 늘리고 순서는 바꾸지 않는다.
